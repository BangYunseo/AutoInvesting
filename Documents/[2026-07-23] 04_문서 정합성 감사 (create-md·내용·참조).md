# 문서 정합성 감사 — create-md 양식·Phase 6 내용·참조

> 📌 **후속 처리 (2026-07-30)** — 이 감사서의 조치 항목은 대부분 집행되었다. 단 **1번(두 API 문서를 서로
> 정합 유지)은 방침을 변경**했다: `API_REFERENCE_TABLE.md`는 `API_REFERENCE.md`의 진부분집합으로 고유
> 정보가 0건이었고, 손으로 정합을 맞추는 방식이 실제로 드리프트를 재발시켰기 때문에 **표 문서를 삭제**하고

## 개요
> `Documents/` 핵심 문서 13개를 (1) create-md 양식, (2) Phase 6 현실 대비 내용 정확성, (3) 내부 참조 무결성 3축으로 읽기전용 병렬 감사한 결과다. 가장 위험한 항목은 `API_REFERENCE.md`·`API_REFERENCE_TABLE.md`가 **이미 삭제된 판단 레이어(Phase 8) 아키텍처 기준으로 남아 있어** 읽는 사람을 심각하게 오도한다는 점이다.

## 배경 / 목적
문서 홈을 `Documents/` 단일로 통합하고 상시 참조 문서를 `Documents/reference/`로 분리한 뒤, 남은 create-md 양식 적용과 내용 현행화를 실제로 손대기 **전에** 각 문서의 실태를 먼저 확정하려고 감사했다. 워크플로우로 문서 13개를 병렬 분석(에이전트당 소스코드·규칙 교차검증, 편집 없이 소견만 반환)했다. 대상은 `reference/` 5개(생성물 CODE_MAP 제외) + 루트 `[2026-07-04] 01~03` + `260702_*` 3개 + `analysis/` 2개다.

### HIGH — 내용이 틀려 읽는 사람을 오도

#### API_REFERENCE.md / API_REFERENCE_TABLE.md (전면 재작성 대상)
- 문서 기준이 "Phase 8", 머리말이 "매매 결정=퀀트 단독 / AI 휴면 / 모니터링·적응형·가중치 A/B 휴면" — Phase 6에서 판단 레이어는 **휴면이 아니라 코드째 제거**됨.
- 실재하지 않는 엔드포인트 다수 문서화: `/api/order/execute`·`/api/order/daily-run`·`/api/order/analyze/{ticker}`, `/api/strategy/*`, `/api/monitoring/*`, `/api/sellplan/*`, `/api/quant/analyze/{ticker}`, `/api/backtest/run`, `/api/sim/*`, `/api/config/gemini-models`, `/api/test/inject-mock`·`test-adaptive`·`send-report`·`health`.
- Phase 6 실재 엔드포인트가 통째로 누락: `POST /api/order/dca-run`, `GET /api/order/sell-preview`, `GET·PUT /api/dca/config`, `GET /api/price/{ticker}`, `GET /api/macro/briefing`, `GET·POST /api/auth/status|setup|login`, `GET /api/config/secret/{key}`.
- 인증 서술이 "x-api-key만 필수" — 실제는 전역 필터가 Bearer 세션토큰(사람) 또는 x-api-key(크론) 중 하나로 통과, `[PublicEndpoint]`(auth status/setup/login)는 면제.
- `GET /api/config` 응답 예시 필드(ACTIVE_STRATEGY·AI_PROVIDER·GEMINI_MODEL 등)가 전부 제거된 것.
- → **실제 9개 컨트롤러(Auth/Config/Dca/Order/Price/Macro/History/Portfolio/Test) 기준으로 전면 재작성.** 포트폴리오 대표작의 API 문서라 우선순위 최상.

#### ONBOARDING_GUIDE.md §3 (브로커 분기 사실오류)
- "IS_PAPER_TRADING=1이거나 키 없으면 SimBroker" → 실제 `SessionManager`는 **KIS 키가 없을 때만** SimBroker, 키가 있으면 항상 KisBroker. Sim/KIS 분기 기준은 "키 유무"이지 IS_PAPER_TRADING이 아님.
- "Kis:Server로 prod/vps 분기" → 실제 prod/vps 분기는 **IS_PAPER_TRADING**('0'=prod)이 단일 기준. `Kis:Server`는 어디서도 읽지 않는 사실상 미사용 값.
- Phase 6 Auth 레이어(세션토큰 로그인 vs x-api-key, /login) 미언급.
- (참고) §4 적립 로직 서술은 외부에서 이미 현행화됨(고정 수량 템플릿).

#### CODE_READING_GUIDE.md
- Step5: IBrokerClient에 **없는** OHLCV 조회를 있다고 서술(GetOhlcvAsync는 Phase 6에서 제거) → 'OHLCV' 문구 삭제.
- Step2: `RunDcaCycleAsync`가 가장 먼저 하는 **월 1회 멱등 가드**(DCA_LAST_RUN_MONTH) 누락 — 과매수 방지 핵심.

#### 260702_시장국면브리핑-설계계획서.md
- "GEMINI_API_KEY는 이미 민감키·Ai:GeminiApiKey 매핑 존재 → 재활용"이 사실오류. Phase 6에서 AI 레이어 제거로 해당 매핑 없음 → "신규 추가 필요"로 정정해야 구현자가 오도되지 않음.
- 깨진 참조: `Documents/worklog/260702_시장국면브리핑.md` → 실제 `Documents/worklog/[2026-07-02] 04_시장 국면 브리핑.md`.

4. **DEVELOPMENT 현행화**(Resend·Tax·sell-preview·Auth/Macro/Price 이력) + 깨진 링크 제거.
5. **01/02 정정** — reference/ 경로·THEME_GUIDE 링크·낡은 서술.
6. **양식 정리** — reference 5개 프론트매터, `260702_*` 5개 개명+프론트매터, analysis 2개 양식.

핵심 판단:
- **개명 대상은 `260702_*` 5개뿐**(나머지는 이름 고정 또는 이미 규격).
