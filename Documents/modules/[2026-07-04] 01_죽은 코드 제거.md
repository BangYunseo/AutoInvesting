# 죽은 코드 제거 (Phase 3 · 1순위)

## 개요
> 제거된 판단 레이어(퀀트/AI)의 잔재를 정리한 모듈 노트다. 원칙은 **동작 보존** — 삭제 대상은 "어디서도 참조되지 않음"을 grep으로 확인한 코드만이다.

## 배경 / 목적
이 작업은 모듈 정리 진행 순서의 1번이다(모듈 우선순위 문서 참조).

Phase 6에서 타이밍 판단 레이어(SmartOrderEngine·퀀트·AI)를 제거했지만, 그 레이어가 쓰던 데이터 구조·메서드 일부가 참조 0인 채 남아 코드 탐색을 오염시키고 있었다. git이 안전망이므로 삭제한다.

## 본문
### 제거한 코드 (참조 0 확인 후)

#### 죽은 DTO 6개 (`Data/DTO/`)
| 파일 | 근거 |
|---|---|
| `AdaptiveThresholdStatusDto.cs` | 자기 정의 파일 외 참조 0 (적응형 임계값 = 제거된 AI 레이어) |
| `DailyTokenUsageDto.cs` | 참조 0 (AI 토큰 비용 모니터링 잔재) |
| `StrategySummaryDto.cs` | 참조 0 (구 전략 요약) |
| `AssetMasterDto.cs` | 참조 0 (종목 마스터 미사용) |
| `PriceRangeDto.cs` | 참조 0 — `GetPriceRangeAsync`는 튜플 `(High, Low)`를 반환해 이 DTO를 쓰지 않았음 |
| `OhlcvDto.cs` | 아래 죽은 메서드 제거로 마지막 사용처 소멸 |

#### 죽은 브로커 메서드 (인터페이스 + 양 구현체)
| 메서드 | 위치 | 근거 |
|---|---|---|
| `GetPriceRangeAsync` | `IBrokerClient`, `KisBrokerClient`, `SimBrokerClient` | 외부 호출처 0 (퀀트 지표용이었음) |
| `GetOhlcvAsync` | 〃 | 유일 호출처가 `GetPriceRangeAsync`뿐 → 함께 사망 |
| `_rng`(난수 필드) | `SimBrokerClient` | `GetOhlcvAsync` 제거로 미사용 |

- **유지(생존 확인)**: `GetCashBalanceAsync`는 `PortfolioController`가 사용 → 삭제하지 않음.

### 검증 방법 (동작 보존)
- 제거 전 베이스라인: `dotnet build` 오류 0, `dotnet test` **12/12 통과**.
- 제거 후 재검증: `dotnet build` 경고 0·오류 0, `dotnet test` **12/12 통과**.
- 미사용 코드만 지웠으므로 실행 경로·주문/적립 로직은 변화 없음.

### 의도적 보류
- **죽은 테이블 스키마 정리**(`TB_SELL_PLAN`, `TB_TOKEN_USAGE`, `TB_AI_PERFORMANCE`, `TB_INVEST_STRATEGY`, `TB_ASSET_MASTER`)는 `create_tables.sql` 및 `DBManager.InitializeDatabase()`의 마이그레이션과 얽혀 있어, **Data 레이어(DBManager) 리팩토링 시** 운영 DB 물리 DROP 여부와 함께 별도로 다룬다. (`TB_MARKET_SNAPSHOT`은 규칙상 보존)
- `appsettings.json`·`AppConfigManager`의 판단 레이어 설정 매핑은 **step 2(AppConfigManager)** 에서 정리한다.

## 정리 / 결론
- 참조 0을 grep으로 확인한 죽은 DTO 6개와 죽은 브로커 메서드(`GetPriceRangeAsync`·`GetOhlcvAsync`·`_rng`)만 제거했다.
- 빌드·테스트가 제거 전후 모두 통과해 동작 보존을 확인했다.
- 죽은 테이블 스키마 정리와 판단 레이어 설정 매핑 정리는 후속 단계로 미뤘다.
