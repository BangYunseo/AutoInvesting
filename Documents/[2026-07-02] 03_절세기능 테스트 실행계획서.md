# 절세 보조 기능 테스트 실행 계획서

## 개요
> 매도 예상 양도세·수수료 계산과 과세 매도 가드(feature/tax-guard)를 브로커/DB/네트워크 없이 결정적으로 검증하는 테스트 실행 계획서다(계획대로 구현·검증 완료). 관련: 설계 계획서 `Documents/[2026-07-02] 02_절세 보조기능 설계계획서.md`, `.agents/rules/code-style-guide.md`(테스트), `.agents/rules/recommended_rules.md`.

## 1. 배경 / 문제의식

라이브 스택(DB·로그인·KIS) 전체를 거쳐 테스트하려니 곁가지(콜드스타트·토큰·500)가 딸려와
"세금 로직이 정말 맞는가"를 깔끔히 검증하기 어렵다. → **테스트를 낮은 계층으로 내려**,
브로커/DB/네트워크 없이 **가짜 데이터를 주입**해 결정적으로 검증한다.

## 2. 테스트 3계층 전략

| 층 | 검증 대상 | 테스트데이터 | 인프라 | 상태 |
|----|-----------|-------------|--------|------|
| **A. 순수함수 단위** | 세금 **계산 로직** | 함수 인자(숫자) | 없음 | ✅ 완료(`TaxEstimatorTests`, 19건) |
| **B. 가짜 브로커 통합** | 컨트롤러 **배선**(취득가→계산→409 가드) | 손으로 만든 `HoldingDto` | 없음(Fake 주입) | ⬜ 본 계획 |
| **C. 라이브 UI 1회** | Alert **문구·UX** | SimBroker 시드 | 앱 실행 | ⬜ 선택 |

원칙: **테스트데이터를 실제 계좌에 만들지 않는다.** `IBrokerClient` 인터페이스로 가짜 객체를 주입한다.

## 3. B 계층 상세 (핵심 — 지금 유일한 공백)

### 3-1. 필요한 seam (주입점)
- `OrderController`는 `SessionManager.GetClient()`로 브로커를 얻는다. 테스트에서 **가짜 브로커**를
  주입할 수 있어야 한다.
- 최소 변경안: `SessionManager`에 **테스트용 클라이언트 주입 생성자/메서드** 추가
  (예: `SessionManager(IBrokerClient preset)` 또는 `internal void UseClientForTest(...)` + `InternalsVisibleTo`).
  운영 경로(파라미터리스 생성자)는 그대로 유지.

### 3-2. 추가 파일
- `Tests/FakeBrokerClient.cs` — `IBrokerClient` 구현. 시드 값 반환:
  - `GetHoldingsAsync` → 지정한 `HoldingDto`(예: QQQM Qty=25, AvgPrice=100)
  - `GetCurrentPriceAsync` → 고정가(예: 200)
  - `GetExchangeRateAsync` → 고정 환율(예: 1300)
  - `PlaceSellOrderAsync` → 가짜 주문번호, `LoginAsync` → true
- `Tests/OrderControllerTaxGuardTests.cs` — 컨트롤러 통합 테스트.

### 3-3. 테스트 케이스 (DB 없이 가능한 범위)
1. **sell-preview 값 검증**: QQQM 취득 $100·현재 $200·환율 1300·수량 25·YTD 0
   → 예상차익 3,250,000원 / 과세표준 750,000 / 예상세금 165,000 / `IsTaxable=true` / 비과세최대수량 검증.
2. **과세 매도 차단**: `manual` SELL, 과세 상황 + `AcknowledgeTax=false`
   → **409(Conflict)** 반환 + `taxEstimate` 포함, **주문 미실행**(가드가 주문·기록 전에 반환).
3. **취득가 불명 처리**: `AvgPrice=0`인 보유종목 → `CostBasisUnknown=true`, 가드 건너뜀(차단 안 함).
4. **비과세 경계**: 수량을 낮춰 차익 ≤ 250만 → `IsTaxable=false`(차단 대상 아님) — preview로 검증.

### 3-4. 범위/한계 (정직 고지)
- **성공 매도(200 경로)는 B에서 제외**: `manual`이 체결 후 `TradeHistoryDAO.Insert`(정적 DB 호출)를
  타므로 DB 없이 검증 불가. → 이 경로는 C(수동) 또는 후속(DAO 추상화) 에서 다룬다.
- `TaxSettings.Load()`는 설정 미초기화 시 기본값(250만/22%/0.0025)로 폴백 → 테스트 결정성 유지.

## 4. C 계층 (선택 — Alert 눈으로 1회)

- SimBroker에 **저가 취득 보유종목 시드**(dev 전용, 예: QQQM 25주 @ $100)를 넣어 시작.
  → 매도 시 화면 Alert 문구·비과세최대수량 안내를 육안 확인.
- 시드는 **개발 모드 한정**(운영 SimBroker 동작 오염 금지). 플래그/조건 게이팅.

## 5. 라이브(Render/KIS) 테스트 방침

- 세금 로직 검증에 **사용하지 않는다**(느림·실계좌 위험·무관 변수). 배포 후 **정상 동작 스모크**로만.
