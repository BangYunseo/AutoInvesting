# 시장 국면 브리핑 기능 설계 계획서

## 개요
> 뉴스·거시 지표(물가·유가·금리·고용)를 읽어 "지금이 어떤 시장 국면인지"를 사람이 이해하도록 설명하는 기능의 설계 계획서다(1단계 구현 완료 / 2~6단계 착수 전). ⚠️ 매수 판단이 아니라 정보·표시 전용(판단 레이어 아님). 관련 규칙: `architecture.md`·`code-style-guide.md`·`recommended_rules.md`·`security.md`·`kis-api-guide.md`. 인계 노트: `Documents/worklog/[2026-07-02] 04_시장 국면 브리핑.md`.

## 1. 목적 / 요청

"지금 사야 한다"는 **매수 판단이 아니라**, *"유가가 내리고 물가가 높아 금리를 못 내리는 국면"* 처럼
**뉴스와 거시 지표를 읽어 지금이 어떤 시장 국면인지 사람이 이해하도록 설명**해 주는 기능.

- 예: 미국 물가(CPI·근원 PCE)·유가(WTI)·금리(10년)·고용(실업률) + 원/달러 환율을 모아
  현재 상황·향후 시나리오·한 줄 결론을 한국어 해설로 제공.
- 데이터 원천은 공식 API(FRED·네이버 검색), 해설은 Gemini(LLM) + 실패 시 규칙 기반 폴백.

## 2. 핵심 원칙 (반드시 지킬 것)

- **정보/보고 전용 레이어.** 매수/매도 "타이밍 판단"이 아니라 **상황 설명**이다.
  Phase 6에서 백테스트로 무가치 확인된 신호/임계값/AI 타이밍과 무관하다. (`recommended_rules.md` 위반 아님)
- **판단 레이어와 물리적 분리(가장 중요한 벽).** `MacroBriefingService`는 **텍스트/DTO만 생산**하고,
  `DcaAccumulationEngine`(매수 수량·타이밍)은 이 결과를 **참조하는 코드가 0줄**이어야 한다.
  매수량에 어떤 숫자도 흘러가지 않는다. ("사라/팔아라"가 아니라 "상황이 이렇다"만.)
- **투자 권유 아님.** 해설 끝에 항상 "공개 데이터 기반 정보 정리이며 매수·매도 권유가 아님" 고지.
- **폴백 우선 설계.** AI 키가 없거나 실패해도 규칙 기반으로 항상 결과를 낸다(앱이 멈추지 않음).
- 순수 계산/해설 조립은 **외부 I/O 없는 순수 함수**로 분리해 단위 검증(`PlanPurchases` 패턴 준수).

## 3. 데이터 소스 & 분석 로직

### 데이터 소스
| 구분 | 지표/내용 | 출처 | 키 |
|------|-----------|------|----|
| 물가 | CPI(`CPIAUCSL`), 근원 PCE(`PCEPILFE`) | FRED | `FRED_API_KEY` |
| 유가 | WTI(`DCOILWTICO`) | FRED | 〃 |
| 금리 | 10년 국채(`DGS10`) | FRED | 〃 |
| 고용 | 실업률(`UNRATE`) | FRED | 〃 |
| 환율 | USD/KRW | 기존 `ExchangeRateService`(Frankfurter, 무키) | 불필요 |
| 뉴스 | 거시/환율 관련 헤드라인 | 네이버 검색 API | `NAVER_CLIENT_ID/SECRET` |
| 해설 | 국면 서술(LLM) | Google Gemini | `GEMINI_API_KEY` |

- 지수형(CPI·PCE)은 전년 동월 대비(YoY)를 직접 계산, 값형(유가·금리·실업률)은 직전 대비 등락.
- 개별 지표 조회 실패는 예외 대신 `error` 필드로 표현("일부만 실패" 허용).

### 해설 4단 구조 (AI·규칙 공통 포맷)
1) 현재 상황 한눈에 (지표별 한 줄)
2) 뉴스 요약 (공통 흐름 3~4문장 — 뉴스 연동 단계에서 채움)
3) 미래 시나리오 (낙관 / 신중 + 성립 조건)
4) 결론 (한 문장) + 투자권유 아님 고지

## 5. Gemini 연동 주의사항 (CheckUSA 디버깅에서 얻은 교훈)

> 외부 프로젝트 CheckUSA에서 동일 Gemini 연동을 붙이다 401/429로 크게 헤맨 경험을 반영한다.

- **호출 방식:** `?key=` 쿼리파라미터 대신 **`x-goog-api-key` 헤더**로 호출한다.
  신형 auth key(`AQ.`로 시작)와 향후 표준에 맞는 방식.
- **기본 모델:** `gemini-2.5-flash` (또는 `gemini-flash-latest`).
  `gemini-2.0-flash`/`1.5-flash`는 계정에 따라 무료 할당량 0(429)이거나 폐기(404)될 수 있음.
- **키 형식 변화:** 구형 `AIza…`(39자)는 2026-09 폐기 예정, 신형 `AQ.…`(auth key)로 전환 중.
  코드가 `AIza` 접두를 검증하면 안 됨(형식 가정 금지).
- **설정 우선순위 함정:** `AppConfigManager`는 환경변수 → DB → appsettings 순.
  운영에서 키를 바꿀 때 **오래된 환경변수가 새 값(DB/설정)을 덮어쓰지 않는지** 유의.
- **실패는 침묵시키지 말 것:** AI 호출 실패 시 사유를 마스킹해 `Logger.Warn`으로 남기고
  규칙 기반으로 폴백. (CheckUSA는 완전 침묵이라 진단이 어려웠음 → 우리는 로깅한다.)
- **429/타임아웃:** Polly 재시도 적용(KIS 클라이언트 패턴 재사용), 하루 1회 호출이라 비용·한도 여유.

## 6. 설정 / 보안

### appsettings.json 신규 `Macro` 섹션 (값은 비워둠 — 실제 키는 환경변수)
```json
"Macro": {
  "_comment": "실제 키는 소스에 두지 않음. 환경변수 FRED_API_KEY / NAVER_CLIENT_ID / NAVER_CLIENT_SECRET / GEMINI_API_KEY 로 주입.",
  "GeminiModel": "gemini-2.5-flash",
  "NewsEnabled": true
}
```
- `AppConfigManager`에 `FRED_API_KEY`·`NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET` 매핑 추가
  (`GEMINI_API_KEY`는 Phase 6에서 AI 레이어와 함께 매핑이 제거됨 → `AppConfigManager`에 민감키·환경변수 매핑 **신규 추가 필요**).
- 민감키는 DB 저장 시 암호화(`CryptoUtil`), 로그 출력 시 마스킹(`security.md`).
- 키가 없어도 규칙 기반·환율로 동작(필수 아님).

## 8. 테스트 계획

- `MacroBriefingService.BuildRuleBasedNarrative` 순수함수 단위 검증(완료):
  물가 높음→신중/주시, 물가 낮음→낙관 여지, 지표 없음→단정 안 함, 항상 투자권유 아님 고지,
  실패 지표 제외.
- `GeminiClient`는 무키/401/429/타임아웃 시 폴백되는지 확인(모킹 또는 통합).
- `IS_PAPER_TRADING=1`(SimBroker) 환경에서 대시보드·이메일 경로 확인.
- **무결합 검증:** `DcaAccumulationEngine`/`DailyExecutionService`가 매수 계산에
  브리핑을 참조하지 않는지 grep으로 확인(1단계 확인 완료).

## 9. 보안 / 규칙 체크

- [ ] API 키(FRED/Naver/Gemini)를 소스·로그·커밋에 포함하지 않음(환경변수/DB, 마스킹).
- [ ] 개인정보·계좌·잔고를 프롬프트/응답/로그에 넣지 않음(공개 거시 지표·뉴스만).
- [ ] 판단 레이어 무결합 벽 유지(엔진이 브리핑 미참조).
- [ ] 빈 catch 금지, `Logger` 사용, 동기 블로킹 없음, `IBrokerClient` 우회 없음.
- [ ] 순수 함수 분리로 검증 가능.
- [ ] "정보 제공·투자권유 아님" 문구 UI/메일 노출.
