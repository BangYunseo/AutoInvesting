## 1. 목적 / 요청

매도 시점에 **이 매도가 세금이 붙는 구간인지**를 사전에 계산해 사용자에게 알려주고,
과세가 발생하면 **금액(예상 세금·수수료)을 명시한 Alert**로 경고해 **함부로 매도하지 못하게** 한다.

예: *"지금 이 수량을 매도하면 양도차익 260만원 중 공제(250만) 초과분 10만원에 대해
예상 세금 22,000원 + 예상 수수료 ○○원이 부과됩니다. 진행하시겠습니까?"*

## 2. 핵심 원칙 (반드시 지킬 것)

- **판단 레이어 아님.** 이것은 매수/매도 "타이밍 판단"이 아니라 **세금 산수 + 정보 제공/경고**다.
  백테스트로 무가치 확인된 신호/AI 타이밍 재도입과 무관하다. (`recommended_rules.md` 위반 아님)
- **자동 매도 금지.** 시스템은 **계산·경고까지만** 하고, 최종 매도 결정은 사람이 한다.
- **추정치 명시.** 환율·취득가 산정방식·실제 수수료가 실제 신고와 다를 수 있으므로 항상 "추정" 표기.
- **세무 조언 아님.** 실제 신고는 홈택스/세무 전문가 확인 안내.
- 순수 계산은 **외부 I/O 없는 순수 함수**로 분리해 단위 검증(프로젝트의 `PlanPurchases` 패턴 준수).

## 3. 계산 로직 (근거 데이터 → 결과)

### 입력 (이미 존재하는 데이터)
- `HoldingDto.AvgPrice` (평균 매입단가 USD) — 취득가. 브로커가 산정한 값 사용(가장 정확).
- 매도 예정 `가격(USD)` (미지정 시 `CurrentPrice`), 매도 `수량`.
- 환율 USD→KRW (`GetExchangeRateAsync`).
- **연초 이후(YTD) 이미 실현한 양도차익 합계(KRW)** — 남은 공제 계산에 필요(§5 지속성).

### 산식 (순수 함수)
```
매도차익(USD)   = (매도가 - 평균매입가) × 수량           // 음수면 손실 → 세금 0
매도차익(KRW)   = 매도차익(USD) × 환율
남은공제(KRW)   = max(0, 2,500,000 - YTD실현차익(KRW))
과세표준(KRW)   = max(0, 매도차익(KRW) - 남은공제(KRW))
예상세금(KRW)   = 과세표준 × 0.22
예상수수료(KRW) = 매도금액(KRW) × 수수료율(설정값, 추정)
비과세최대수량  = 남은공제(KRW)가 소진되지 않는 최대 정수 수량 (차익>0일 때)
과세여부        = 예상세금 > 0
```

### 설정값 (appsettings.json 신규 `Tax` 섹션 — 매직넘버 금지 원칙)
```json
"Tax": {
  "AnnualDeductionKrw": 2500000,
  "Rate": 0.22,
  "EstimatedSellFeeRate": 0.0025   // KIS 해외 수수료 추정치 — 실제 값 확인 후 조정
}
```

## 4. 구현 범위 (레이어별)

| 레이어 | 파일 | 작업 |
|--------|------|------|
| Core | `Core/TaxEstimator.cs` (신규) | 순수 함수 `EstimateSellTax(avgPrice, sellPrice, qty, fx, ytdGainKrw, settings)` → 결과 DTO. 외부 I/O 없음(단위 검증 대상) |
| Data(DTO) | `Data/DTO/SellTaxEstimateDto.cs` (신규) | 차익/남은공제/과세표준/예상세금/예상수수료/비과세최대수량/과세여부 |
| Data(DAO) | `Data/DAO/TradeHistoryDAO.cs` | `GetYtdRealizedGainKrw(int year)` 추가. SELL 기록의 실현차익 합산 |
| Data(스키마) | `Data/DBManager.cs` | `TB_TRADE_HISTORY`에 nullable 컬럼 추가(ALTER TABLE, 하위호환): `COST_BASIS_USD`, `REALIZED_GAIN_KRW`, `FX_RATE`. SELL 시 기록 |
| API | `Controllers/OrderController.cs` | ① `GET /api/order/sell-preview?ticker=&qty=&price=` → 추정 결과 반환. ② `manual`의 SELL 경로에 **세금 가드**: 과세 매도인데 `acknowledgeTax=true`가 없으면 **409 + 추정정보** 반환(서버측 강제) |
| API(DTO) | `ManualOrderRequest` | `bool AcknowledgeTax` 필드 추가 |
| Frontend | `Frontend/src/pages/Order.jsx` | 매도 시 주문 전 `sell-preview` 호출 → 차익/세금/수수료 표시. 과세면 금액 담은 `confirm()`(Alert) 후에만 `acknowledgeTax:true`로 제출 |

### 흐름 (매도)
```
[사용자가 매도 수량 입력]
     → (프론트) GET /api/order/sell-preview  → 차익·예상세금·예상수수료·비과세최대수량 표시
     → [매도 클릭]
         ├─ 과세 아님(공제 내): 기존대로 바로 확인 후 주문
         └─ 과세: 금액 명시한 Alert("예상 세금 22,000원 + 수수료 ○○원 — 진행?")
                 → 사용자 확인 시에만 acknowledgeTax:true 로 POST /api/order/manual
                 → (서버) 과세인데 ack 없으면 409로 차단(프론트 우회 방지)
```

## 5. 지속성 / YTD 실현차익 추적

- **문제:** 남은 공제를 알려면 "올해 이미 실현한 차익 합계"가 필요. 과거 SELL 기록엔 차익이 없음.
- **방안:** 이 기능 배포 후 발생하는 SELL부터 `REALIZED_GAIN_KRW`를 기록 → `GetYtdRealizedGainKrw`로 합산.
- **한계(정직 고지):**
  - 배포 이전 매도, **증권사 앱에서 직접 한 매도**는 시스템이 모른다 → YTD가 과소집계될 수 있음.
  - 보완: 프리뷰 화면에 **"이미 사용한 공제액 수동 입력"** 필드 제공(기본값 = 시스템 집계치).
  - 공제는 **모든 해외주식 합산 연 250만**(종목별 아님) — 합산 기준으로 계산.

## 6. 테스트 계획

- `TaxEstimator` 순수 함수 단위 검증(신규 테스트 프로젝트 활용):
  - 차익 240만 → 세금 0 / 차익 260만 → 22,000원 / 손실 → 0 / 남은공제 0 → 전액 과세 / 비과세최대수량 경계.
- `IS_PAPER_TRADING=1`(SimBroker)로 매도 프리뷰·가드·409 동작 확인.
- ALTER TABLE 후 기존 데이터 보존 확인.

## 8. 확정된 결정 (사용자 승인 260702)

1. **가드 강도: 서버 강제 차단.** 과세 매도인데 `acknowledgeTax=true`가 없으면 `OrderController.manual`이 **409 + 추정정보**로 차단(프론트 우회 불가, 기존 보유수량 가드와 일관).
2. **수수료 포함: 세금 + 예상 수수료 동시 표기.**
3. **MVP = 프리뷰 + 경고만 먼저.** YTD 실현차익 자동 집계(§5 스키마 확장·`REALIZED_GAIN_KRW` 기록·`GetYtdRealizedGainKrw`)는 **2차로 연기**.

### MVP(1차) 범위 확정
- 신규: `Core/TaxEstimator.cs`(순수 함수), `Data/DTO/SellTaxEstimateDto.cs`, `appsettings.json > Tax` 섹션.
- API: `GET /api/order/sell-preview` + `manual`의 SELL 세금 가드(409) + `ManualOrderRequest.AcknowledgeTax`.
- Frontend: `Order.jsx` 매도 프리뷰 표시 + 과세 시 금액 명시 Alert → ack 후 제출.
- **YTD 공제 사용액은 프리뷰 화면에서 "수동 입력"**(기본 0). DB 스키마 변경 없음.

### 2차(후속) 범위
- `TB_TRADE_HISTORY` nullable 컬럼(`COST_BASIS_USD`/`REALIZED_GAIN_KRW`/`FX_RATE`) ALTER TABLE 추가.
- SELL 시 실현차익 기록 + `GetYtdRealizedGainKrw(year)`로 남은 공제 자동 계산(수동 입력은 보정용으로 유지).
