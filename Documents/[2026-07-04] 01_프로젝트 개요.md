# 프로젝트 개요

## 개요
> 코드베이스 분석·리팩토링 워크플로우의 Phase 0(사전 탐색) 산출물로, 코드를 수정하지 않고 프로젝트의 전체 그림·실행 방법·외부 의존성·시크릿 위치를 기록한다.

## 배경 / 목적
이 문서는 코드베이스 분석·리팩토링 워크플로우의 **Phase 0(사전 탐색)** 단계에서 작성되었다. 코드를 수정하지 않고, 프로젝트의 전체 그림·실행 방법·외부 의존성·시크릿 위치만 기록한다. 이 워크플로우의 분석 산출물은 당초 별도 `docs/` 폴더에 두었으나, 2026-07-23 문서 홈을 `Documents/` 하나로 통합하며 `Documents/`로 이관했다.

대상 프로젝트는 정해진 주기(외부 크론잡)에 해외 ETF를 **기계적으로 적립(DCA) 매수**하는 **Headless REST API 서비스**다. 타이밍/퀀트/AI 판단 레이어는 백테스트로 가치 없음이 확인되어 Phase 6에서 전면 제거됐다.

## 본문

이 프로젝트에는 이미 손으로 쓴 문서가 `Documents/`에 여럿 있다. 탐색 과정에서 **기존 문서 중 낡은(stale) 것**을 발견했으며, 아래는 현재 정확도 판정이다(리팩토링 마무리 단계 Phase 4에서 정리 대상).

| 기존 문서 | 상태 | 비고 |
|---|---|---|
| `Documents/ONBOARDING_GUIDE.md` | 🟢 대체로 최신 | Phase 6(DCA 전환) 반영됨 |
| `Documents/CODE_READING_GUIDE.md` | 🟢 대체로 최신 | Phase 6 반영됨 |
| `Documents/DEVELOPMENT.md` | 🟡 확인 필요 | 전체 개발 이력 (Phase 1에서 정독 예정) |
| `Documents/CODE_MAP.md` | 🔴 **낡음** | 삭제된 `SmartOrderEngine`, `AiMarketAnalyzer`, `GeminiMarketAnalyzer`, `Core/Quant` 등을 여전히 나열. 자동 생성물(`regen-codemap.ps1`)이라 재생성 필요 |
| `Documents/API_REFERENCE.md` | 🔴 **낡음** | "Phase 8 기준 / 퀀트 단독 / AI 결정 경로" 서술 = Phase 6 이전 상태 |

### 진입점과 실행 방법
- **백엔드 진입점**: `Program.cs` → `Program.Main()`
  - `WebApplication` 호스트 구성 → 컨트롤러(전역 `ApiKeyAuthAttribute` 필터) → 헬스체크 → 정적 파일(React) → SPA fallback(`index.html`)
  - DI: `DBManager`(싱글턴), `SessionManager`(싱글턴), `DailyExecutionService`(Scoped)
- **실행**: `dotnet run` (루트에서). 빌드는 `dotnet build`.
- **프론트엔드**: `Frontend/`에서 `npm install` → `npm run dev`(개발) / `npm run build`(배포용, `dist/`).
- **적립 사이클 트리거**: `POST /api/order/dca-run` (헤더 `x-api-key`, 202 즉시 반환 후 백그라운드 처리)
- **배포**: Render.com (`https://autoinvesting.onrender.com`), `Dockerfile` 기반.

### 외부 연동 지점

| 대상 | 용도 | 관련 코드 |
|---|---|---|
| 한국투자증권(KIS) REST API | 로그인/현재가/OHLCV/잔고/주문 | `Core/KisBrokerClient.cs`, `Core/KisTokenManager.cs` |
| (시뮬레이션) | 모의 브로커 — 실 API 없이 검증 | `Core/SimBrokerClient.cs` |
| Frankfurter API | 환율(USD/KRW) 조회·캐싱 | `Utils/ExchangeRateService.cs` |
| Resend API | 적립 리포트/예외 이메일 발송 | `Utils/NotificationService.cs` |
| PostgreSQL | 설정·거래내역·로그 영속화 (로컬 localhost / 배포 `DATABASE_URL`) | `Data/DBManager.cs` |
| GitHub Actions (크론) | 매일 KST 23:40 `dca-run` 호출 (월 1회는 엔진 멱등 가드가 보장) | `.github/workflows/daily-run.yml` |

- **실전/모의 분기**: `SessionManager`가 `IS_PAPER_TRADING`(appsettings `Trading.IsPaperTrading`)로 `SimBrokerClient`/`KisBrokerClient` 선택.
- **증권사 API 직접 호출 금지**: 반드시 `IBrokerClient` 인터페이스 경유 (규칙).

### 설정값·시크릿 위치 (⚠️ 값이 아닌 위치·용도만)

| 위치 | 성격 | 내용(값 아님) |
|---|---|---|
| `appsettings.json` | 비민감 기본설정 (git 추적) | Trading/Kis(server,계좌구분)/Dca 템플릿·예산/빈 시크릿 placeholder |
| `appsettings.local.json` | **로컬 시크릿 파일 (git 무시됨)** | KIS 키/시크릿·API 접근키 등 (내용 미확인·미출력) |
| 환경변수 | **배포 시크릿 주입** | `DATABASE_URL`, `KIS_APP_KEY`/`KIS_APP_SECRET`/`KIS_ACCOUNT_NO`, `RESEND_API_KEY`, `ADMIN_EMAIL`, `MASTER_KEY`, `API_ACCESS_KEY` 등 |
| GitHub Actions Secrets | 크론 인증 | `CRON_API_KEY` |
| `MASTER_KEY` (`Utils/CryptoUtil.cs`) | 시크릿 암복호화 + 토큰 서명 | 미설정 시 평문 저장 경고 |

- `.gitignore`가 `appsettings.local.json`, `*.local.json`, `*.secrets.json`, `*.env`, `*.key` 차단 확인됨.
- Access Token은 메모리 보관, 로그 출력 시 마스킹 (규칙 `security.md`).
- **조직 보안정책**: 개인정보(주민번호/휴대폰/계정/암호)·DB 접속정보는 프롬프트/자료/커밋 금지.

### 테스트 코드
- **존재함** (xUnit, 별도 프로젝트 `Tests/AutoInvest.Tests.csproj`):
  - `Tests/DcaAccumulationEngineTests.cs` — 배분 로직(`PlanPurchases`) 단위 검증
  - `Tests/DcaSettingsTests.cs` — 템플릿/월배정 설정 로직
- **커버리지 범위**: 핵심 순수함수(적립 계획)와 설정 로직에 집중. 컨트롤러/브로커/외부연동/DAO는 자동화 테스트 없음(수동·SimBroker 검증에 의존).
- 리팩토링 시 각 모듈의 스모크 테스트가 필요하면 이 프로젝트에 추가 (Phase 3).

### 안전 유의사항 (자금/주문 관련 — 최우선 보수적)
- **실거래 전환 위험**: 현재 모의투자 기준으로 크론이 매일 호출. 실거래 계좌로 바꾸면 월 예산을 매일 소진해 ~30배 과매수 위험. 엔진 멱등 가드(`DCA_LAST_RUN_MONTH`)가 월 1회를 보장하도록 설계됨. (상세: `Documents/DEVELOPMENT.md` "실거래 전환 시 필수 변경")
- 주문/키/시크릿을 다루는 코드(`KisBrokerClient`, `KisTokenManager`, `CryptoUtil`, `OrderController`)는 리팩토링 우선순위를 낮추고, 손댈 때 반드시 사용자 확인.

## 정리 / 결론
- 대상은 해외 ETF를 기계적으로 적립(DCA)하는 Headless REST API 서비스이며, 판단 레이어는 Phase 6에서 전면 제거됐다.
- 실행은 `dotnet run`으로 하고, 적립 사이클은 `POST /api/order/dca-run`으로 트리거하며 Render.com에 배포된다.
- 기존 `Documents/` 문서 중 `CODE_MAP.md`·`API_REFERENCE.md`는 낡았고 `THEME_GUIDE.md`는 무효로, Phase 4 정리 대상이다.
- 온보딩/리딩 가이드의 "목표비중" 서술과 현재 규칙의 "고정 수량" 모델이 불일치하므로 Phase 1 아키텍처 트레이싱에서 실제 코드로 확정해야 한다.
- 실거래 전환 시 월 예산을 매일 소진하는 ~30배 과매수 위험이 있어 멱등 가드로 월 1회를 보장하며, 주문/키/시크릿 코드는 사용자 확인 후에만 손댄다.
