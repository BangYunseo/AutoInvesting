# 실거래 전환 준비 — 월 1회 적립 멱등 가드 + 크론 주기 변경

## 개요
> 개발용 모의 계좌를 실전투자 계좌로 전환하기 위해, 월 예산을 매일 소진하는 과매수를 막는 "월 1회 적립 멱등 가드"를 엔진에 추가하고 일일 크론 주기를 조정한 작업 기록이다.

## 배경 / 목적
개발용(모의) 계좌를 실전투자 계좌로 전환하려 한다. 실전 전환 시 가장 큰 위험은 **월 예산을 매일 소진(~30배 과매수)**이므로, 코드에서 이를 먼저 막아야 한다.

사용자 요청: 적립 실행일을 **매월 10일** 기준으로 하되, **그날 적립이 안 됐으면 다음 날에도(성공할 때까지) 재시도**하는 방식.

작업 브랜치: `feature/live-account-transition` (main 기준 분기).

## 본문
### 설계 결정
- 부분 체결: **하나라도 성공하면 당월 완료**로 판정 (다음 날 스킵).
- 수동 실행(dca-run 직접 호출)도 **동일하게 당월 가드 적용** (강제 우회 없음).
- "안 됐으면 다음 날 재시도"는 크론만으로 불가 → **크론은 10일~말일 매일 발사**, 실제 1회 실행 여부는 **엔진 진입점의 멱등 가드**가 판정.

### 구현 계획
1. `DailyExecutionService.RunDcaCycleAsync`에 당월 가드 추가:
   - KST 현재 월(`yyyy-MM`)을 `TB_APP_CONFIG`의 `DCA_LAST_RUN_MONTH`와 비교.
   - 같으면 매수 스킵(보고서에 사유 기록). 다르면 실행.
   - 매수 성공(체결 1건 이상) 시 `DCA_LAST_RUN_MONTH`를 현재 월로 저장.
   - 거래이력 대신 마커를 쓰는 이유: 수동 단일 매수가 월 적립을 오판하지 않도록.
2. `.github/workflows/daily-run.yml` cron: `40 14 * * *`(매일) → `40 14 10-31 * *`(10일~말일 매일).
3. 문서 갱신: `DEVELOPMENT.md` 전환 노트, yml 주석.
4. `dotnet build` + SimBroker 모드로 가드 검증(연속 2회 실행 시 2번째 스킵).

### 진행 경과
- 브랜치 생성 완료. README 표정렬 변경은 `feature/manual-order-holdings`에 stash 보관.
- 실행일 정책 변경: 사용자가 "월초에 빨리 내는 것 선호" → cron을 10일~말일이 아니라 **1~31일(매일)**로. 가드가 월 1회를 보장하므로 "월초부터 처음 성공하는 날 1회 적립".
- 구현 완료: `DailyExecutionService` 당월 멱등 가드 + `DCA_LAST_RUN_MONTH` 마커, cron `40 14 1-31 * *`, DEVELOPMENT.md 전환 노트 갱신.
- `dotnet build` 성공(경고 0, 오류 0).

### 사용자 테스트 결과 (260701)
- 실계좌 자격증명으로 `dca-run` 실행 시 "장 운영시간 아님"으로 매수 거부 확인 → 로그인·인증·계좌번호·주문 파이프라인 정상(주문 단계 도달). 사용자 승인 → main 머지 진행.
- 미해결(사용자 후속 확인 예정): 적립설정(템플릿·월배정) 부분 추가 점검.

### 실전 스위치 정정
- 현재 main의 `SessionManager`는 실전/모의를 **`KIS_SERVER`**(`prod`/`vps`)로 분기한다. `IS_PAPER_TRADING`은 "키 없으면 Sim" 폴백 게이트일 뿐 도메인을 바꾸지 않는다.
- `feature/manual-order-holdings` 브랜치는 이를 `IS_PAPER_TRADING` 단일 스위치로 리팩터함 → 머지 시점에 배포된 코드 기준으로 실전 변수를 확인할 것.
