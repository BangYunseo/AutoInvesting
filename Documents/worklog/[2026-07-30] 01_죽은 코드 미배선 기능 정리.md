# 죽은 코드 미배선 기능 정리

## 개요
> 전체 구조 감사에서 확인된 "참조 0건" 코드·자산·스키마·문서 중복을 5단계 순서로 제거한다. 브랜치 `refactor/dead-code-cleanup`에서 작업하고, 사용자 테스트 승인 전에는 `main`에 머지하지 않는다.

## 배경 / 목적
Phase 6에서 판단 레이어를 제거했지만 그 자리에 남은 잔재(레거시 스키마 DDL·마이그레이션, 죽은 CSS 클래스, Vite 스캐폴드 자산)와, 만들었으나 화면에 배선되지 않은 기능(Macro/FRED 국면 브리핑)이 코드베이스에 그대로 남아 있다. 빌드·배포·설정 키를 소모하면서 아무 값도 만들지 않으므로 정리한다.

정리 대상 판정 기준은 하나다. **"참조가 실제로 0건인가"** — 문서에 언급되어 있다는 사실은 참조로 세지 않는다.

### 실행 순서

리스크 낮은 것부터 올린다. 각 단계마다 커밋을 끊고, C# 변경 단계는 `dotnet build`(오류 0)와 `dotnet test`로 확인한다.

1. 스캐폴드 잔재 — `App.css`, `assets/*`, `public/icons.svg`, `Templates/`(+`csproj` 복사 규칙)
2. 죽은 스키마·CSS — `DBManager` 마이그레이션, `create_tables.sql` DDL·시드, `index.css` 죽은 클래스, `History.jsx` 없는 배지 modifier
3. Macro/FRED 스택 — 컨트롤러·서비스·클라이언트·DTO 2종·테스트
4. 중복 축약 — 알림박스 CSS 클래스화, `ExchangeRateService` 파서 통합, `TestController` 매수 경로 제거, `NotificationService` 공개 표면 축소, `appsettings.json` 죽은 키
5. 문서 — SSOT 중복 문서, API 3중 사본, 죽은 설계서, 죽은 참조 남은 스크립트·커맨드

### DB 관련 주의

`create_tables.sql`과 `DBManager`에서 제거하는 것은 **스크립트의 DDL 문구뿐**이다. 운영 DB의 기존 테이블·데이터는 건드리지 않는다. 신규 DB 생성 시 죽은 테이블을 더 만들지 않게 하는 것이 목적이다.

운영 DB에서 실제 `DROP TABLE`이 필요하면 이 작업 범위 밖에서 별도로 진행한다. 순서는 백업 → 건수 확인(`SELECT COUNT(*)`) → 트랜잭션 → 롤백 스크립트 준비다.

### 5단계에서 밝혀진 것 — 기존 문서 드리프트

문서 참조 무결성을 47개 문서에 병렬 스윕한 결과, 이번 삭제로 생긴 드리프트 외에 **기존 드리프트 다수**가
드러났다. 그중 하나는 단순 오기가 아니라 규칙 충돌이었다.

`code-style-guide.md`의 파일 배치 **MUST** 표가 `퀀트 모듈 | Core/Quant/ | QuantFilter.cs` 행을 유지하고
있었다. 디렉토리와 클래스 모두 Phase 6에서 삭제됐는데, 규칙은 남아 "퀀트성 코드는 `Core/Quant/`에 두라"고
지시하고 있었다. `recommended_rules.md`의 판단 레이어 재도입 금지와 정면으로 부딪히는 상태였고, 같은 파일이
CLAUDE.md를 통해 매 세션 로딩되므로 에이전트가 금지된 레이어를 규칙에 맞게 되살릴 수 있는 경로였다.

`kis-api-guide.md`도 제거된 `GetOhlcvAsync`·`GetPriceRangeAsync`를 매핑 표에 유지해, 판단 레이어용 일봉
조회 재구현을 유도할 수 있었다. 둘 다 이번에 제거했다.

교훈: **코드를 지울 때 그 코드를 지시하던 규칙까지 같이 지워야 한다.** 규칙만 남으면 지운 코드가 규칙을
근거로 되살아난다.

## 정리 / 결론

1~5단계 모두 적용 완료. `main` 미머지 상태이며 사용자 테스트 승인 전까지 머지하지 않는다.

- **코드**: Macro/FRED 스택 6파일, `POST /api/test/buy`, `Templates/DailyReportTemplate.html`,
  프론트 미사용 자산 5개, `App.css`, `DBManager` ALTER 9건+`RunMigration`, 죽은 CSS 5클래스,
  죽은 설정 키 6개, `create_tables.sql`의 죽은 DDL 2종·시드 삭제.
- **개선**: 환율 파서 2개 → `ParseKrwRate` 순수함수 1개(0 이하 환율 예외 승격), 알림박스 13곳 →
  `.alert` 공용 클래스, `send-test-email`이 발송 실패를 삼키던 버그 수정.
- **검증**: `dotnet build` 오류 0, `dotnet test` 40/40 통과(Macro 5건 삭제·환율 4건 추가),
  `npm run build` 성공, eslint 문제 10→9(baseline 대비 신규 0).
- **보존 재확인**: `TB_MARKET_SNAPSHOT`(데이터·DDL 모두), 테스트 seam, `TaxEstimator`,
  KIS 거래소 매핑, 환율 2차 폴백.

### 남은 일

- 사용자 테스트 → 승인 후 `main` 머지 → `git push origin main`(재배포 트리거, 명시적 확인 후).
- 운영 DB 물리 DROP(`TB_ASSET_MASTER`·`TB_INVEST_STRATEGY` 등)은 **미착수**. 백업 → 건수 확인 →
  트랜잭션 → 롤백 스크립트 세트로 별도 진행. `TB_MARKET_SNAPSHOT`은 DROP 후보가 아니다.
- Macro 기능이 다시 필요하면 화면과 같은 작업 단위로 도입한다(백엔드만 먼저 만들지 않는다).
