# 죽은 코드 미배선 기능 정리

## 개요
> 전체 구조 감사에서 확인된 "참조 0건" 코드·자산·스키마·문서 중복을 5단계 순서로 제거한다. 브랜치 `refactor/dead-code-cleanup`에서 작업하고, 사용자 테스트 승인 전에는 `main`에 머지하지 않는다.

## 배경 / 목적
Phase 6에서 판단 레이어를 제거했지만 그 자리에 남은 잔재(레거시 스키마 DDL·마이그레이션, 죽은 CSS 클래스, Vite 스캐폴드 자산)와, 만들었으나 화면에 배선되지 않은 기능(Macro/FRED 국면 브리핑)이 코드베이스에 그대로 남아 있다. 빌드·배포·설정 키를 소모하면서 아무 값도 만들지 않으므로 정리한다.

정리 대상 판정 기준은 하나다. **"참조가 실제로 0건인가"** — 문서에 언급되어 있다는 사실은 참조로 세지 않는다.

## 본문

### 삭제 판정 근거

| 대상 | 참조 확인 결과 |
|------|----------------|
| Macro/FRED 스택 | `App.jsx` 라우트 6개에 Macro 페이지 없음. `Frontend/` 전체에서 `api/macro` 검색 0건. 메일 보고서(`DailyExecutionService`)도 미사용 |
| `Frontend/src/App.css` | `main.jsx`가 `index.css`만 임포트 — 이 파일은 번들에 포함되지 않음 |
| `Templates/DailyReportTemplate.html` | 코드 참조 0건. 보고서 HTML은 `DailyExecutionService.BuildCard`가 직접 생성 |
| `assets/react.svg`·`vite.svg`·`hero.png`, `public/icons.svg` | 참조 0건. PWA 아이콘은 `favicon.svg`에서 생성(`vite.config.js`) |
| `TB_ASSET_MASTER`·`TB_INVEST_STRATEGY` | 코드 참조 0건 (해당 DAO 없음). `DBManager`의 ALTER만 남아 있었음 |

| 죽은 CSS | `.grid-2`·`.progress-bar`·`.progress-container`·`.text-profit`·`.text-loss` jsx 사용 0건 |
| `Dca:Enabled` | 읽는 코드 0건 |
| `/api/test/buy` | `/api/order/manual`에서 가드만 뺀 중복 경로. 실전 모드는 자기 자신을 403으로 차단 |

체스터튼의 울타리 — 이상해 보여도 이유가 확인된 것은 남긴다.

### 실행 순서

리스크 낮은 것부터 올린다. 각 단계마다 커밋을 끊고, C# 변경 단계는 `dotnet build`(오류 0)와 `dotnet test`로 확인한다.

1. 스캐폴드 잔재 — `App.css`, `assets/*`, `public/icons.svg`, `Templates/`(+`csproj` 복사 규칙)
2. 죽은 스키마·CSS — `DBManager` 마이그레이션, `create_tables.sql` DDL·시드, `index.css` 죽은 클래스, `History.jsx` 없는 배지 modifier
3. Macro/FRED 스택 — 컨트롤러·서비스·클라이언트·DTO 2종·테스트
4. 중복 축약 — 알림박스 CSS 클래스화, `ExchangeRateService` 파서 통합, `TestController` 매수 경로 제거, `NotificationService` 공개 표면 축소, `appsettings.json` 죽은 키
5. 문서 — SSOT 중복 문서, API 3중 사본, 죽은 설계서, 죽은 참조 남은 스크립트·커맨드

### DB 관련 주의

`create_tables.sql`과 `DBManager`에서 제거하는 것은 **스크립트의 DDL 문구뿐**이다. 운영 DB의 기존 테이블·데이터는 건드리지 않는다. 신규 DB 생성 시 죽은 테이블을 더 만들지 않게 하는 것이 목적이다.

운영 DB에서 실제 `DROP TABLE`이 필요하면 이 작업 범위 밖에서 별도로 진행한다. 순서는 백업 → 건수 확인(`SELECT COUNT(*)`) → 트랜잭션 → 롤백 스크립트 준비다.
