# 260629 적립 매수 템플릿 + 월별 배정

- 상태: 진행중 (구현·빌드 완료, 실서버 검증 예정)
- 작성/갱신: 260629

## 목적 / 요청
매달 동일 적립이 아니라, 여러 "매수 템플릿"(예산+종목별 수량)을 만들어 두고 월별로 배정해
그 달엔 해당 템플릿대로 매수. (예: 1월→공격형, 2월→안정형) 비중 자동결정은 차차.

## 결정 (사용자)
- 적용 방식: **월 캘린더 예약** (1~12월에 템플릿 배정, 현재 월에 맞는 템플릿 자동 적용).
- 공격/안정 분류·비율(70:30) 표시: **이번엔 제외**, 다음 단계. (대시보드에서 보유자산 타입 분석 +
  리밸런싱 추천 방향으로 갈 예정 — ⚠ 규칙상 "리밸런싱 금지"와 닿아 범위 정의 필요, 아래 참고)
- 전제: 달력 월(1~12) 매년 반복 / 미배정 달은 매수 스킵 / 기존 단일 설정은 "기본" 템플릿으로 자동 이관.

## 진행 / 결정
- 데이터 모델: `DcaTemplate`{Id,Name,BudgetKrw,Quantities} 신설(Data/DTO).
- DcaSettings: 단일 수량 → 템플릿 목록(`DCA_TEMPLATES`) + 월배정(`DCA_MONTH_MAP`). `Load()`는
  현재(KST=UTC+9) 월의 템플릿을 해석해 (수량,예산) 반환 → 엔진/`DailyExecutionService`는 무변경.
  레거시 `DCA_QTYS`/appsettings는 '기본' 템플릿으로 자동 이관(동작 보존).
- DcaController: GET=템플릿+월배정+현재월+활성템플릿 / PUT=전체(templates+monthMap) 검증 후 저장.
- 프론트 DcaConfig.jsx 재작성: 템플릿 목록(추가/복제/삭제/선택) + 선택 템플릿 편집기(이름·예산·
  종목 수량·티커검증) + 월별 배정 그리드(현재월 강조) + 전체 저장.
  서버 로드 행은 status='saved'(신뢰), 선택 시 현재가 검증, 편집 시 재검증 요구.
- 빌드: 백엔드/프론트 0 오류.

## 남은 일 / 다음 단계
- 실서버 검증: 템플릿 추가/편집/삭제, 월 배정, 저장→재조회, dca-run이 현재 월 템플릿대로 매수하는지.
- (다음 단계) 공격/안정 자산 분류 + 대시보드 보유자산 타입 분석 + 리밸런싱 "추천" 표시.
  ⚠ 규칙 충돌 검토 필요: recommended_rules "리밸런싱 재추가 금지"는 자동 타이밍 판단 제거가 취지.
  자동 매매가 아닌 "정보성 추천(사람이 템플릿으로 실행)"이 허용 범위인지 사용자와 규칙 확정 후 진행.
