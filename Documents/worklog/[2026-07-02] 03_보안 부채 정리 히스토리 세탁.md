# 보안 부채 정리 및 히스토리 세탁

## 개요
> public 전환에 대비해 보안 부채를 정리한 작업 기록이다. 개인정보 제거, gitleaks 시크릿 스캔 도입, git 히스토리 세탁 3종을 수행하고 원격까지 반영을 완료했다.

## 배경 / 목적
public 전환 대비 보안 부채(메모리 public-transition-pending)를 정리한다. 작업 순서는 "문서 최신화 → 보안 부채 정리"이며, 보안 정리는 개인정보 제거·gitleaks 도입·히스토리 세탁 3종으로 구성한다.

## 본문
### 진단
git 히스토리를 전수 스캔한 결과 실제 자격증명(비밀번호/API키/계좌번호)이 커밋된 이력은 **없음**을 확인했다.

- Password 항목은 플레이스홀더에서 빈값으로만 이어졌고, AIza 흔적 0건, local/secrets 파일은 미커밋이었다.
- 히스토리에 남은 유일한 민감정보는 본인 관리자 이메일과 네이버 ID뿐이었다.
- 따라서 메모리에 있던 "시크릿 로테이션" 전제는 성립하지 않는다.

### 개인정보 제거 (A)
`Utils/NotificationService.cs`에 환경변수 `ADMIN_EMAIL` 우선 폴백을 추가하고, `appsettings.json`의 `Smtp.Username`과 `AdminEmail`을 비웠다. `Smtp.Username`은 이미 사용되지 않는 죽은 설정이었다.

### gitleaks CI 도입 (B)
`.github/workflows/gitleaks.yml`을 추가했다. push/PR/수동 트리거에서 전체 히스토리를 스캔한다.

A/B 변경은 빌드·테스트(12건) 통과 후 커밋했다.

### 히스토리 세탁 (C)
`pip install git-filter-repo` 후 `--replace-text`로 히스토리의 이메일/ID를 치환했다.

- 백업: `../AutoInvesting-backup-260702.bundle` (전체 히스토리).
- 함정: Write 도구가 저장소 경로(`!!!` 포함)에 replacements 파일을 생성하지 못해, 임시폴더에 bash로 생성해 해결했다. `Program.cs`의 미커밋 변경은 patch로 보관한 뒤 원복 → 재적용했다.
- 전 히스토리에서 대상 네이버 ID 잔존 0건을 확인한 뒤 origin을 재등록하고 `--force-with-lease`로 성공적으로 푸시했다.

### 커밋 순서
force-push 후 기준의 이번 세션 커밋 순서는 다음과 같다.

1. test: DCA 배분·템플릿 선택 단위 테스트 도입
2. docs: DEVELOPMENT 문서 템플릿 모델 최신화 및 폐기 주석 정리
3. chore: 개인정보 설정 제거 및 gitleaks 시크릿 스캔 도입
4. docs: Program 클래스 요약 주석 간소화

이 커밋들 위에서 filter-repo가 전 히스토리 해시를 재작성했다.

### 별건 작업
사용자 지시로 `Program.cs`의 Program 요약 주석을 간소화(세션 밖 변경)해 `docs:` 단일 커밋으로 처리했다.

## 정리 / 결론
- 최종 상태: local과 origin이 동일하며, 미푸시 0, 원격 반영본에 개인정보 잔존 0을 확인했다.
- **Render 환경변수 `ADMIN_EMAIL` 설정이 필수**다. 설정하지 않으면 알림 메일 수신자가 없어 조용히 스킵된다.
- `MASTER_KEY`는 최근 정상 배포로 보아 이미 설정된 것으로 추정한다.
- gitleaks CI 첫 실행 결과(초록/빨강)를 확인하고, 필요 시 `.gitleaks.toml` allowlist를 조정한다.
- 불필요하면 백업 번들과 임시 patch는 삭제할 수 있다.
