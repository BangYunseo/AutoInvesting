# 적립 메일 종합 1통 통합

## 개요
> 매일 적립 사이클에서 종목별로 여러 통 오던 메일(실은 매수 실패 종목마다 개별 발송)을, 실패·예산 경고까지 사이클 종료 시 한 통의 종합 보고서로 통합한 작업의 인계 노트다.

## 목적 / 요청
매일 적립 사이클에서 "종목별로 메일이 여러 통 오는" 구조를 종합 메일 1통으로 바꿔달라는 요청.
조사 결과, 성공 시엔 이미 보고서 1통이었고 "종목별 메일"의 정체는 매수 실패 종목마다 개별 발송하던
경로였음. 실패·예산경고까지 사이클 종료 시 한 통의 보고서로 통합.

## 계획
1. 모든 메일 발송 지점 열거 (완료: 4곳 — 보고서/예산경고/실패/테스트).
2. `AccumulateAsync` 반환을 결과 집계 객체로 바꿔 실패·경고를 즉시 메일 대신 결과에 적재.
3. `SendDcaReportAsync`가 성공+실패+예산경고를 한 본문에 조립해 1통 발송.
4. 빌드·기존 테스트 회귀 확인.

## 진행 / 결정
- 발송 지점: `DcaAccumulationEngine`의 예산초과(개별 아님)·매수실패(**종목별 개별** ← 문제),
  `DailyExecutionService`의 사이클 보고서(이미 종합 1통), `TestController`(수동, 무관).
- 결과 홀더 `DcaCycleResult`(Filled/Failures/BudgetWarning) + `DcaBuyFailure` 신설(Data/DTO, 순수 데이터).
- `AccumulateAsync` 반환 타입 `List<TradeHistoryDto>` → `DcaCycleResult`. 호출자는 `DailyExecutionService` 1곳뿐이라 파급 작음. 기존 단위테스트는 순수함수 `PlanPurchases`만 검증 → 시그니처 변경에도 무영향.
- 보고서 표시 결함 동시 정정: 종목별 수량이 항상 "1주"로 표기되던 `g.Count()` → `g.Sum(x => x.Qty)`.
- 검증: `dotnet build` 경고 0/오류 0, `dotnet test` 41개 전부 통과.
- **근본 원인 이슈(별개)**: 사용자가 "DCA 매수 실패: XXX" 메일을 실제로 받고 있음 = 매수가 매일 실패 중이라는 신호. 통합 후엔 보고서 1통의 "매수 실패 내역"에 실패 사유(예외 메시지)가 모여 진단이 쉬워짐. 실패 사유 확인 필요.
- 실패 집계 단위테스트는 공유 FakeBrokerClient 확장/DAO 추상화가 필요해 이번 범위서 제외(후속 과제).
- (추가) 보고서 매수·실패 내역 표시를 리스트→**카드형**으로 변경. 이메일 호환 위해 인라인 스타일 div(`BuildCard` 헬퍼). 종목당 카드 1장(배지·종목·단가·수량), 실패 카드는 사유 포함.

## 남은 일 / 다음 단계

  실패 집계 경로는 Sim에서 재현 어려움(항상 성공) — 실서비스 실패 메일 본문의 사유로 확인.
- 근본 원인: 기존 "DCA 매수 실패" 메일 본문의 오류 메시지 확인 → 매수 실패 원인 진단(장 세션/현재가/계좌 설정 등).
