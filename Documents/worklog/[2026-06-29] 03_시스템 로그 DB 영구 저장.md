# 시스템 로그 DB 영구 저장 전환

## 개요
> 거래내역의 "시스템 로그" 탭이 파일 기반이라 날짜 조회가 깨지고 재배포 시 소실되던 문제를, 로그를 PostgreSQL에 영구 적재하도록 전환해 재시작에도 보존되고 날짜별 조회가 정상 동작하게 한다.

## 배경 / 목적
거래내역의 "시스템 로그" 탭이 세 가지 문제를 안고 있었다.

1. 파일명 형식 불일치 버그로 날짜 조회가 깨져 있음.
2. `retainedFileCountLimit:7`로 7일만 보관됨.
3. Render의 휘발성 파일시스템 때문에 재배포·재시작 시 로그가 사라져 사실상 당일 것만 보임.

이를 해결하기 위해 로그를 PostgreSQL에 영구 적재해 재시작에도 보존되고 날짜별 조회가 정상 동작하게 한다.

## 본문
### 구현 계획
1. `create_tables.sql`에 `TB_SYSTEM_LOG`(+ LOG_DATE 인덱스) 추가 (IF NOT EXISTS, 멱등).
2. `Data/DAO/SystemLogDAO.cs` 신규: Insert / GetByDate / GetAvailableDates / PruneOlderThan.
3. `Utils/Logger.cs`: Data 직접 참조로 인한 순환(Data→Utils) 방지를 위해 `Action` 훅 `DbSink`만 두고, Info/Warn/Error/Fatal/LogQuant에서 Persist 호출(실패는 콘솔로만 — 재귀 방지).
4. `Program.cs`: DBManager 초기화 직후 `Logger.DbSink = SystemLogDAO.Insert` 연결 + 90일 prune.
5. `Controllers/HistoryController.cs`: 파일 대신 DB(SystemLogDAO)에서 로그 조회. 응답 형식 유지(프론트 무변경).

### 진행 / 결정
- 결정: Logger는 Data를 참조하지 않고 `DbSink` 델리게이트만 노출 → 조립 지점(Program.cs)에서 주입. (레이어 의존성 규칙 + 순환 회피)
- 결정: DB 적재는 DBManager 생성(Lazy 팩토리) 완료 후에만 활성화 → 초기화 중 재귀/Lazy 예외 방지.
- 결정: 응답 라인 형식을 `[시각] [LEVEL] 메시지`로 통일해 프론트 색상 규칙([ERROR]/[WARN]/[QUANT]) 유지.

### 검증 및 다음 단계
- [완료] dotnet build 오류 0 / 경고 0.
- [대기] 사용자 테스트: 앱 실행 → 거래내역 → 시스템 로그 탭에서 오늘 날짜 로그가 보이는지, 날짜 조회 및 "사용 가능한 로그 날짜" 버튼이 동작하는지 확인.
- [대기] 사용자 테스트 OK 후 커밋(main 직접 작업).

## 정리 / 결론
- 로그를 파일 대신 `TB_SYSTEM_LOG`에 적재해 재시작·재배포에도 보존되고 날짜별 조회가 복구된다.
- Logger는 `DbSink` 델리게이트만 노출하고 주입은 Program.cs에서 수행해 Data→Utils 순환과 초기화 중 재귀를 회피했다.
- 빌드는 통과했으며, 사용자 테스트 OK 이후 main에 직접 커밋한다.
