- 상태: 완료 (구현·빌드·문서 동기화 완료, 실서버 배포 후 사용자 검증 예정)
- 작성/갱신: 260629

## 목적 / 요청
적립 설정을 "목표비중(%) 기반"에서 **사람이 종목별 고정 수량(주)을 직접 지정**하는 모델로 전환.
- 사람이 정하는 값: 종목(티커) + 매 사이클 매수 수량(+/− 조절)
- 비중(%)·매수금액은 수량×현재가로 자동 계산 → **읽기 전용 표시**(사람이 조절 불가)
- 티커는 현재가 API로 실재 검증(존재하는 종목만 저장), 우측에 실시간 가격 표시
- 예산은 초과 경고용 상한(수량을 줄이지 않음)
- 화면 상단 "ETF 개수" 입력 삭제, "목표비중(%)" 섹션 → "ETF 설정"
> 직전 커밋의 "%(100 기준)·ETF 개수 균등 분배"는 요청 오해였고, 본 작업에서 정정.

## 계획
1. 백엔드: DcaSettings(비중→수량), DcaAccumulationEngine(고정수량), DailyExecutionService 호출 갱신
2. 신규 가격조회 API(GET /api/price/{ticker}) — 현재가 + 티커 검증 겸용
3. DcaController GET/PUT를 quantities 계약으로 변경
4. appsettings Dca:Targets → Dca:Quantities
5. 프론트 DcaConfig.jsx 재작성 (수량 스테퍼/티커검증/실시간가격/읽기전용 비중)
6. SSOT 규칙·README·에이전트 미러 문서 동기화

## 진행 / 결정
- 엔진 의미 변경 확정(사용자): 매 사이클 **고정 주수** 매수. 목표비중 배분 루프 폐기.
- 티커 확정 방식 확정(사용자): 입력 → 현재가 API 즉시 검증(자동완성 드롭다운 X).
- `PlanPurchases` 순수함수 유지(MUST): 시그니처 변경 — (quantities, exchangeRate, priceUsd, out totalCostKrw) → 현재가 있는 종목만 지정 수량 그대로 계획 + 총 매수금액 산출.
- 설정 키 변경: DB `DCA_TARGETS`(weights) → `DCA_QTYS`(int). 옛 키는 레거시로 남기되 더 이상 읽지 않음(임의 삭제 안 함).
- 예산 초과는 경고 로그 + 메일만, 수량 그대로 진행.
- SimBroker는 모르는 티커에 기본가 $100을 반환 → sim 모드에선 모든 티커가 유효하게 보임(실검증은 KIS 모드에서 동작). 테스트 시 유의.
- 빌드: 백엔드 `dotnet build` 0 오류 / 프론트 `npm run build` 정상.
