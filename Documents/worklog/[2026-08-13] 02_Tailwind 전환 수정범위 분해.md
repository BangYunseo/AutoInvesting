# Tailwind 전환 수정범위 분해

## 개요
> AutoInvesting 프론트엔드에 Tailwind CSS를 신규 도입할 때 실제로 수정해야 하는 지점을 파일·줄 단위로 분해한 문서다. 편집 지점 420곳을 SAFE / CAUTION / DANGER 3단계로 분류하고, S0~S6 단계별 작업분해구조와 단계별 검증·롤백 수단을 함께 적었다. 결정 항목(D1~D8)은 비워 두었다.

## 배경 / 목적

`[2026-08-13] 01_AutoInvesting UI 리디자인 결정목록.md`의 조사에서, 그 문서가 전제한 스택(Next.js + Tailwind + shadcn/ui + TypeScript)이 이 프로젝트에 존재하지 않는다는 사실이 확인됐다. 실제는 Vite 8 + React 19 + 손으로 쓴 `index.css` 1150줄이다.

따라서 Tailwind는 "버전 업그레이드"가 아니라 **신규 도입 + 전 화면 마크업 재작성**이다. 그 규모를 착수 전에 실측으로 확정하기 위해 이 분해를 만들었다.

이 프로젝트는 실자금이 오가는 개인 운영 도구이고 테스트 러너가 없다. 전환이 깨지는 방식은 대부분 **빌드 통과 + 콘솔 오류 없음 + 화면만 틀림**이므로, 각 단계에 기계적 검증 수단을 붙이는 것이 이 문서의 핵심 목적이다.

조사 방식: 6대상 파일별 인벤토리를 병렬로 뽑고, 위험도 판정마다 별도 검증 단계에서 과대·과소평가 양쪽을 반증 시도했다. **위험도 재분류가 31건 발생했으며 아래 수치는 전부 재분류 반영본이다.**

### 0-2. `@import` 순서 — 실측 정정

`Frontend/src/index.css:1`은 **BOM + `@import url('...Inter...')`** 이며, 파일 내 유일한 `@import`입니다(다음 at-rule은 `:442 @keyframes` — 확인). v4 진입점도 `@import "tailwindcss";`이므로 **@import 두 개가 연속하면 순서와 무관하게 CSS 명세 위반이 아닙니다.** "폰트가 통째로 무시된다"는 v3(`@tailwind` 지시문) 시나리오입니다.

다만 회피가 더 싸므로 선택지를 남깁니다.

| 선택지 | 내용 | 트레이드오프 |
|---|---|---|
| A | 폰트를 `index.html:7` 뒤에 `<link rel="preconnect">` + `<link rel="stylesheet">`로 이관, `index.css:1` 삭제 | import 재배치 이슈(#16663/#17494) 자체를 회피. 렌더 왕복 1회 감소. `index.html` 1파일 추가 접촉 |
| B | `@import "tailwindcss";`를 1행, 폰트 @import를 2행 | 파일 1개만 접촉. #16663 해결 여부 **미확인**(이슈 closed, 수정 버전 미명시) |

### 0-3. preflight 도입 여부 — 갈리는 지점

이것이 **S0의 유일한 실질 분기**이며, 이후 모든 단계의 기준선입니다.

| | preflight **켬** | preflight **끔** |
|---|---|---|
| 진입 형태 | `@import "tailwindcss";` | `@layer theme, base, components, utilities;` + `theme.css` / `utilities.css`만 import (preflight.css 제외) |
| `index.css:59-63` 자체 리셋 | 완전 중복 → 삭제 | 유지 (유일한 리셋) |
| **A. `.ccy-toggle button`(920-929) 등 `font-family` 미선언 `<button>`** | preflight의 `font: inherit`로 **일제히 Inter로 바뀜** → 글자폭 변화, 통화/매수매도 토글 레이아웃 흔들림. `index.css:876`이 `font-family: inherit`을 수동으로 박아둔 것이 이 문제를 이미 한 번 만났다는 증거 | 변화 없음 |

| `border` 유령 테두리 | 없음 — `border-width`만/`border-style`만 선언한 곳 0건, 66건 전부 숏핸드(확인) | — |
| `img`/`svg`/`ul`/`ol` 정규화 | **노출 0** — `src/` 전체 JSX에 `<svg`/`<img`/`<ul`/`<ol`/`<li` 0건 | — |
| 버튼 `cursor` | 이미 면역 — `index.css:483,632,682,885,927,1048`이 명시 선언 | — |
| `h1~h4` / `a` 승부 | `.card h2`(0,1,1)·`.section-header h2`(0,1,1)·`.nav-link`(0,1,0)가 preflight(0,0,1)를 **명시도로 이김**. 실질 피해는 `index.css:122`(h3 1.1rem) 하나 → `ConfirmDialog.jsx:18`, `Order.jsx:73` 모달 제목 축소뿐 | — |
| 롤백 | `preflight.css` 한 줄 제거 | 한 줄 추가 |

**판단 재료**: preflight가 주는 이득(리스트·이미지·테이블 정규화)의 실측 노출면이 0이고, 손실은 A·B 두 건이 실주문 폼에서 확실히 발생합니다. 다만 끄면 `index.css:59-63` 리셋을 영구히 들고 가야 합니다. **결정은 사용자 몫으로 남깁니다.**

### 착수 전 반드시 정해야 하는 것

D1~D8 여덟 개가 미결이며, 그중 셋은 **뒤로 미루면 같은 지점을 두 번 고치게 된다**.

- **D2 (preflight 켬/끔)** — S0의 기준선. 끄면 `index.css:59-63` 리셋을 영구히 들고 간다. 켜면 `.ccy-toggle button` 등 `font-family` 미선언 버튼이 일제히 Inter로 바뀌고 `::placeholder` 색이 전 폼에서 밝아진다.
- **D3 (`html{font-size:15px}` 처리)** — 간격 94건의 착지 여부가 여기서 갈린다. 삭제하면 rem 폰트 39건과 Tailwind 스케일이 +6.67% 확대되는데 px 간격 67건은 고정이라 전 화면 비율이 틀어진다. 빌드·린트는 통과한다.
- **D4 (`--accent-blue` 참조 유지 여부)** — `index.css:757-762`의 매수=빨강 캐스케이드 생사가 걸린다. `@theme inline`을 쓰면 죽는다. S2 착수 전 10줄 스파이크로 실증할 것.

### 가장 위험한 지점

1. **`.manual-order--buy` 변수 스와핑**(`index.css:757-767`) — 조상 1곳에서 하위 8지점 색을 뒤집는 캐스케이드. 유틸리티에 대응물이 없다. 처리를 틀리면 매수 카드가 파랑이 되고, 그건 주문 방향 오인이다.
2. **`Order.jsx:232-703`** — 상태 21개, fetch 3개, 핸들러 7개, 매도수량 클램프, 주문 제출. 스타일 0건. diff에 등장하면 그 자체가 오류다.
3. **`HoldingsTable` 헤더 6 : 셀 6 대응** — 열이 한 칸 밀려도 빌드·린트 모두 통과한다. 매입가 자리에 현재가가 찍힌 표를 보고 사람이 매도를 판단한다.
4. **동적 클래스 조립** — `bg-${tone}` 형태는 JIT가 못 봐서 **프로덕션 빌드에서만** 색이 사라진다. 개발 서버에서는 안 잡힌다.
