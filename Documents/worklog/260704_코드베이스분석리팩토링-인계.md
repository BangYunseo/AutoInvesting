## 목적 / 요청

바이브 코딩으로 만들어져 오너(사용자)가 전체 구조를 충분히 이해 못 하는 상태의 코드를,
**동작을 바꾸지 않으면서(behavior-preserving)** 이해·정리·문서화한다. 목표는 상품화가 아니라
"오너가 내 도구로 신뢰할 수 있게 이해하기". 지시서의 Phase 0→4를 순서대로, 각 Phase/모듈 종료 시
**요약 보고 + 사용자 확인** 후 다음으로.

## 절대 원칙 (반드시 준수)

1. **동작 보존** — 매매/실행 로직의 의미를 바꾸는 변경은 반드시 먼저 설명·확인. 구조/문서 정리만.
2. **자금/주문·시크릿 코드는 최우선 보수적** — 우선순위 뒤로, 건드릴 땐 별도 확인.
3. **한 번에 하나씩, 작은 커밋** — 모듈 하나 끝날 때마다 커밋 + 요약 보고.
4. **문서화 동시 진행**.
5. **모르면 추측 금지, 질문**.

## 사용자가 내린 결정 (중요 — 그대로 따를 것)

- **레거시/죽은 코드 = 삭제.** 사유: 불필요한 코드가 실제 작업을 오염시킴.
  - 단 경계: **죽은 "코드"는 삭제(git 복구 가능)**, **운영 DB "테이블 물리 DROP"은 영구 손실이라 별도 확인**.
  - `TB_MARKET_SNAPSHOT` 은 규칙상 **보존**(수정·삭제 금지).
- **문서 홈 통합 = 방식 (A)**: 워크플로우 동안 `docs/` 에 쌓고, **Phase 4에서 `docs/` 를 정식 문서 홈으로 확정**,
  낡은 `Documents/` 파일(CODE_MAP·API_REFERENCE 등)은 대체/폐기해 단일 홈으로 통합.
- **모듈 이해 문서 형식 = "오너 관점 요약" + "라인 바이 라인 정독" 두 파트** (남은 모든 모듈에 동일 적용).
  - Part1: 한 문장 역할 / 입력→처리→출력·부작용 / 이 코드가 내리는 결정(평문) / 함정 / 만질 곳 / 불명확 항목.
  - Part2: 핵심 메서드 라인 바이 라인 해설. 끝에 "리팩토링 노트"(무엇을·왜·동작보존 근거).
- **커밋은 진행하되 push는 하지 않음** (push = Render 재배포 트리거 → 항상 명시적 확인 후).
- 설정 파일: `appsettings.local.json` 은 로컬 전용(미필수, Render는 환경변수 사용). `appsettings.json` 은 유지(기본값 시드/문서 역할, 시크릿 칸은 공란).

## 모듈 루프 (Phase 3에서 모듈마다 반복)

- `docs/00_overview.md`: 개요·실행법·외부연동·시크릿 위치(이름만)·DB테이블·테스트 유무.

### Phase 3 · 1순위 죽은 코드 제거 (완료)

- 삭제 메서드: `IBrokerClient`/`KisBrokerClient`/`SimBrokerClient` 의 `GetPriceRangeAsync`·`GetOhlcvAsync` + Sim의 미사용 `_rng`.

### Phase 3 · 2순위 AppConfigManager + DcaSettings (완료)
- `AppConfigManager`: 호출처 0인 판단 레이어 키 매핑 삭제(전략/리밸런싱/AI/합의/FX), `SensitiveKeys`에서 `GEMINI_API_KEY` 제거.

### Phase 3 · 3순위 SimBrokerClient (완료)
- 문서: `docs/modules/SimBrokerClient.md`(2파트 형식). 정독 중 **주석-코드 드리프트 발견**: 클래스 주석의
  "기준가 ±3% 범위에서 생성"은 죽은 코드 제거로 `_rng`가 사라지며 없어진 동작 → 실제는 기준가 그대로 반환.
- 리팩토링(사용자 승인 후): ① 잘못된 ±3% 주석 정정, ② 시뮬 기준가·환율을 2026-07 근사 스냅샷으로 갱신
  (SCHD 32.39 / QQQM 293.42 / GLD 378.13 / JEPI 56.71 / SPLG 80.00, 환율 1530). **수량 로직은 가격 무관 → 동작 보존.**
  값은 "실시간 아님·수동 갱신" 주석 명시. 라이브 조회로 바꾸지 않음(결정성 유지).
- 테스트: `Tests/SimBrokerClientTests.cs` 신규 10건(로그인/현재가 결정성·폴백 $100/환율 양수/예수금 상수/
  가중평균 평단/일부·전량 매도/무보유 매도). 시장값은 관계·양수만, 시뮬 내부 계약은 정확히 검증(값 갱신에 안 깨짐).
- 빌드 경고0오류0·**테스트 22/22**(기존 12 + 신규 10). 함수명은 기존 테스트 규칙대로 한글 유지(사용자 확인).

  딸려 들어감. 변경 경로를 **명시적으로** add 한다. (1순위 커밋 때 실수 → amend로 제거한 이력 있음.)

- push는 사용자 명시 확인 후에만.
