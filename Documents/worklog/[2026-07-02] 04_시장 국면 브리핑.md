# 시장 국면 브리핑 (정보 전용 레이어) 도입

## 개요
> 유가·물가·금리·환율과 뉴스를 읽어 현재 시장 국면을 파악하는 정보/보고 전용 레이어를 도입한다. 브리핑 결과는 매수 판단 로직에 한 줄도 흘러가지 않는다.

## 배경 / 목적
사용자 요청: 다른 프로젝트(CheckUSA/MacroWatch)를 분석하고, AutoInvesting에 도입 가능성·실효성을 검토. 결론적으로 "사라/팔아라 판단"이 아니라 **"지금 시장이 어떤 국면인지(유가·물가·금리·환율 + 뉴스) 읽어서 상황을 파악"** 하는 기능을 원함.

핵심 제약(합의): 이 기능은 **정보/보고 전용 레이어**로만 붙인다. Phase 6에서 백테스트로 폐기한 판단 레이어(신호/임계값/AI 타이밍) 재도입 금지 규칙을 지키기 위해, 브리핑 결과가 `DcaAccumulationEngine`(매수 수량·타이밍)에 **한 줄도 흘러가지 않는 벽**을 유지한다.

## 본문
### 사용자 결정
- 해설 엔진 = **Gemini** (CheckUSA와 동일). 하루 1회라 무료 티어로 충분.
- 노출 위치 = **대시보드 읽기전용 위젯 + 적립 리포트 이메일 첨부**.

### 구현 계획 (6단계, 기능별 커밋)
1. DTO + FredClient + 규칙기반 MacroBriefingService + MacroController  ← **완료**
2. GeminiClient 연동 (폴백 유지)
3. NaverNewsClient 통합 (해설 2)번 항목에 뉴스 반영)
4. Frontend "시장 현황" 페이지 + 네비 링크
5. 적립 리포트 이메일에 브리핑 HTML 블록 첨부 (best-effort)
6. 설정 플럼빙(FRED/Naver 키 매핑) + 문서 갱신(project_overview/DEVELOPMENT)

### 진행 상황 및 결정
- **1단계 완료·검증**:
  - `Data/DTO/MacroIndicatorDto.cs`, `Data/DTO/MacroBriefingDto.cs`
  - `Utils/FredClient.cs` — CPI/CorePCE/WTI/DGS10/UNRATE, YoY 계산, 1시간 캐싱, 개별 실패는 Error 필드(예외 없음). FRED_API_KEY는 AppConfigManager(env→DB→appsettings)에서 읽음.
  - `Core/MacroBriefingService.cs` — 규칙 기반 4단 해설. `BuildRuleBasedNarrative`는 순수함수(단위검증용)로 public 노출. 환율은 기존 `ExchangeRateService` 재사용.
  - `Controllers/MacroController.cs` — `GET /api/macro/briefing` (GET이라 DcaController처럼 별도 x-api-key 없음).
  - `Tests/MacroBriefingServiceTests.cs` — 5개 통과.
- **판단 레이어 무결합 확인**: Core에서 MacroBriefing을 참조하는 곳은 서비스 자신뿐. 엔진 미변경.
- **빌드**: 경고 0 / 오류 0. 테스트 5/5 통과.
- 설계 근거: AppConfigManager에 `GEMINI_API_KEY`가 이미 민감키+`Ai:GeminiApiKey` 매핑으로 남아 있어 2단계에서 재활용 가능. ExchangeRateService가 static이라 같은 스타일로 static 구성(DI 배선 최소화).

### 다음 단계
- 2단계부터 이어가면 됨: `Utils/GeminiClient.cs`(generateContent REST + Polly) 만들고 `MacroBriefingService`의 규칙기반 자리에 "AI 우선 → 실패/무키 시 규칙기반 폴백" 삽입.
- 3~6단계는 계획대로.
- 실제 라이브 지표·AI 해설은 키 필요(FRED/Naver/Gemini, 모두 무료). 키 없어도 규칙기반·환율은 동작.
- 커밋: 아직 안 함(사용자 확인 후). 값이 아닌 키 "이름"만 문서화(보안).

## 정리 / 결론
- 시장 국면 브리핑은 **정보/보고 전용 레이어**로, `DcaAccumulationEngine`의 매수 의사결정과 완전히 분리된 벽을 유지한다.
- 1단계(DTO + FredClient + 규칙기반 MacroBriefingService + MacroController)는 완료·검증됨(빌드 경고/오류 0, 테스트 5/5 통과).
- 이후 2~6단계(Gemini 연동, 네이버 뉴스 통합, 프론트 페이지, 이메일 첨부, 설정 플럼빙·문서 갱신)를 순서대로 진행한다.
- 라이브 지표·AI 해설에는 무료 API 키(FRED/Naver/Gemini)가 필요하되, 키가 없어도 규칙기반 해설과 환율은 동작한다. 커밋은 사용자 확인 후 진행하며, 값이 아닌 키 이름만 문서화한다.
