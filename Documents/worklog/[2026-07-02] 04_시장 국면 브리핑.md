# 시장 국면 브리핑 (정보 전용 레이어) 도입

> ⚠️ **2026-07-30 폐기** — 1단계 산출물이 프론트·메일 어디에도 배선되지 않아 소비자가 0인 죽은 코드로
> 판정되어 전량 삭제되었습니다(`MacroController`·`MacroBriefingService`·`FredClient`·DTO 2종·테스트 5건).
> 2~6단계는 착수하지 않았습니다. 아래 내용은 **당시 설계·결정의 시점 기록**이며 현재 코드에는 존재하지
> 않습니다. 재도입 정책은 `.agents/rules/project_overview.md` 참조("다시 필요해지면 화면과 함께 도입").

## 개요
> 유가·물가·금리·환율과 뉴스를 읽어 현재 시장 국면을 파악하는 정보/보고 전용 레이어를 도입한다. 브리핑 결과는 매수 판단 로직에 한 줄도 흘러가지 않는다.

## 배경 / 목적
사용자 요청: 다른 프로젝트(CheckUSA/MacroWatch)를 분석하고, AutoInvesting에 도입 가능성·실효성을 검토. 결론적으로 "사라/팔아라 판단"이 아니라 **"지금 시장이 어떤 국면인지(유가·물가·금리·환율 + 뉴스) 읽어서 상황을 파악"** 하는 기능을 원함.

핵심 제약(합의): 이 기능은 **정보/보고 전용 레이어**로만 붙인다. Phase 6에서 백테스트로 폐기한 판단 레이어(신호/임계값/AI 타이밍) 재도입 금지 규칙을 지키기 위해, 브리핑 결과가 `DcaAccumulationEngine`(매수 수량·타이밍)에 **한 줄도 흘러가지 않는 벽**을 유지한다.

## 본문
### 사용자 결정
- 해설 엔진 = **Gemini** (CheckUSA와 동일). 하루 1회라 무료 티어로 충분.
- 노출 위치 = **대시보드 읽기전용 위젯 + 적립 리포트 이메일 첨부**.

### 구현 계획 (6단계, 기능별 커밋)
1. DTO + FredClient + 규칙기반 MacroBriefingService + MacroController  ← **완료**
2. GeminiClient 연동 (폴백 유지)
3. NaverNewsClient 통합 (해설 2)번 항목에 뉴스 반영)
4. Frontend "시장 현황" 페이지 + 네비 링크
5. 적립 리포트 이메일에 브리핑 HTML 블록 첨부 (best-effort)
6. 설정 플럼빙(FRED/Naver 키 매핑) + 문서 갱신(project_overview/DEVELOPMENT)

### 진행 상황 및 결정
- **1단계 완료·검증**:
  - `Data/DTO/MacroIndicatorDto.cs`, `Data/DTO/MacroBriefingDto.cs`
  - `Utils/FredClient.cs` — CPI/CorePCE/WTI/DGS10/UNRATE, YoY 계산, 1시간 캐싱, 개별 실패는 Error 필드(예외 없음). FRED_API_KEY는 AppConfigManager(env→DB→appsettings)에서 읽음.

    **사실오류**였다 — 해당 매핑은 Phase 6에서 제거되어 신규 추가가 필요했다.

- 1단계(DTO + FredClient + 규칙기반 MacroBriefingService + MacroController)까지 만들고 검증했으나

  남았다.** 2026-07-30 죽은 코드 정리에서 1단계 산출물 6파일 전량 삭제.

  만들고 끊으면 소비자 0인 코드가 남아 빌드·설정 키·문서만 소모한다.
