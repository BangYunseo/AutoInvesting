# 260701 실거래 전환 준비 — 월 1회 적립 멱등 가드 + 크론 주기 변경

- 상태: 진행중
- 작성/갱신: 260701
- 브랜치: `feature/live-account-transition` (main 기준 분기)

## 목적 / 요청
개발용(모의) 계좌를 실전투자 계좌로 전환하려 한다. 실전 전환 시 가장 큰 위험은
**월 예산을 매일 소진(~30배 과매수)**이므로, 코드에서 이를 먼저 막아야 한다.
사용자 요청: 적립 실행일을 **매월 10일** 기준으로 하되, **그날 적립이 안 됐으면
다음 날에도(성공할 때까지) 재시도**하는 방식.

## 결정사항
- 부분 체결: **하나라도 성공하면 당월 완료**로 판정 (다음 날 스킵).
- 수동 실행(dca-run 직접 호출)도 **동일하게 당월 가드 적용** (강제 우회 없음).
- "안 됐으면 다음 날 재시도"는 크론만으로 불가 → **크론은 10일~말일 매일 발사**,
  실제 1회 실행 여부는 **엔진 진입점의 멱등 가드**가 판정.

## 계획
1. `DailyExecutionService.RunDcaCycleAsync`에 당월 가드 추가:
   - KST 현재 월(`yyyy-MM`)을 `TB_APP_CONFIG`의 `DCA_LAST_RUN_MONTH`와 비교.
   - 같으면 매수 스킵(보고서에 사유 기록). 다르면 실행.
   - 매수 성공(체결 1건 이상) 시 `DCA_LAST_RUN_MONTH`를 현재 월로 저장.
   - 거래이력 대신 마커를 쓰는 이유: 수동 단일 매수가 월 적립을 오판하지 않도록.
2. `.github/workflows/daily-run.yml` cron: `40 14 * * *`(매일) → `40 14 10-31 * *`(10일~말일 매일).
3. 문서 갱신: `DEVELOPMENT.md` 전환 노트, yml 주석.
4. `dotnet build` + SimBroker 모드로 가드 검증(연속 2회 실행 시 2번째 스킵).
