# 적립 설정 비중 %(100 기준) 전환 및 ETF 개수 자동 분배

## 개요
> 적립 설정 페이지에서 비중을 0.4 같은 분수 대신 100% 기준(40%)으로 다루고, ETF 개수를 입력하면 100%를 자동 균등 분배해 각 종목의 비중·금액을 자동 표시하도록 개선한 작업이다.

## 배경 / 목적
적립 설정 페이지에서 비중을 0.4 같은 분수 대신 100% 기준(40%)으로 다루고, ETF 개수를 입력하면 100%를 자동 균등 분배하며 각 종목이 예산에서 차지하는 비중·금액을 자동 표시하도록 개선한다. 비중 합계는 100%를 넘을 수 없게 하고, 투자 규모는 비중이 아니라 월 예산으로 조정한다.

## 본문
### 진행 계획
1. 백엔드 호환 확인 (`PlanPurchases`는 비중을 0~1 분수로 비교 → 저장은 분수 유지)
2. 프론트에서 %로 표시·입력, 저장 시 /100, 로드 시 ×100 변환
3. ETF 개수 입력 → 행 개수 조정 + 100% 정수 균등 분배 / 균등 분배 버튼
4. 비중 입력 시 합계 100% 초과분 클램프 + 저장 가드
5. 행별 실제 비중·금액(예산 기준) 실시간 표시

### 백엔드 호환과 변환 방향
- 백엔드(`DcaAccumulationEngine.PlanPurchases`)는 `gap = targets - currentWeight`로 currentWeight(0~1 분수)와 직접 비교 → 저장값은 합계 1 기준 분수여야 정상 동작. 따라서 백엔드 무변경, 프론트에서만 %↔분수 변환(로드 ×100 / 저장 /100).

### 비중 상한과 투자 규모 레버
- 비중 합계 100% 초과 불가: 입력 단계에서 (100 - 다른 종목 합)으로 클램프, 저장 시에도 100% 초과면 차단. "100% 권장"이 아닌 강제 상한.
- 투자 규모 레버는 월 예산. 예산 변경 시 비중은 그대로, 행별 금액만 재계산.

### 빌드 검증
- `npm run build` 통과.

## 정리 / 결론
- 백엔드는 손대지 않고 프론트에서만 %↔분수 변환을 처리해 저장 포맷(분수) 호환을 유지했다.
- 비중 합계 100%는 권장이 아니라 강제 상한으로, 입력·저장 두 단계에서 초과를 차단한다.
- 투자 규모는 비중이 아니라 월 예산으로 조정한다.
- 사용자 화면 확인 후 이상 없으면 종결한다. 필요 시 합계 강제 정규화 옵션 추가를 검토한다.
