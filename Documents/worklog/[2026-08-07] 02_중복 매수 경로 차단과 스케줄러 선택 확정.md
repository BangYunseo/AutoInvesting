# 중복 매수 경로 차단과 스케줄러 선택 확정

## 개요
> 같은 달에 두 번 매수할 수 있던 코드 경로 두 건을 막고, 트리거를 GitHub Actions 하나로 유지하기로 확정했습니다.

## 배경 / 목적
2026-08-01부터 실계좌로 집행 중이므로 중복 매수는 곧 실자금 손실입니다. 이번에 막은 두 경로는 형태가 같습니다 — **조용히 빈 값·빈 목록이 되어 성공한 것처럼 통과하는 실패**입니다. 여기에 GitHub Actions 플랫폼 장애로 트리거가 아예 돌지 않은 일이 겹쳐, 스케줄러 대안까지 함께 검토했습니다.

## 본문

### 월 적립 가드를 fail-closed로 (`Core/DailyExecutionService.cs`)
`DCA_LAST_RUN_MONTH`·`DCA_FORCE_RUN_MONTH`를 `AppConfigManager.Get`으로 읽고 있었습니다. `Get`은 "DB 조회 실패"와 "값 없음"을 같은 기본값(`""`)으로 뭉개고, DB보다 환경변수를 먼저 집습니다. Neon 콜드 스타트가 한 번 삐끗하면 `lastRunMonth == ""`가 되어 가드가 통과하고, 이미 매수한 달에 또 매수했습니다. 동명 환경변수 하나로도 가드가 영구 무력화됐습니다.

두 키를 `AppConfigManager.TryReadDb`(DB 전용)로 바꾸고, 조회 실패 시 **매수하지 않고** 보고 메일을 보낸 뒤 반환합니다(fail-closed). 판정 근거를 못 읽으면 사는 쪽이 아니라 멈추는 쪽이 안전합니다. 부수 효과로 이 두 키의 환경변수 가림 위험도 사라졌습니다.

### 잔고 조회 rt_cd 검사 (`Core/KisBrokerClient.cs`)
`GetHoldingsAsync`가 `rt_cd`를 검사하지 않고 `output1`을 읽었습니다. KIS는 업무 오류를 HTTP 200 + `rt_cd != "0"`(+ `output1` 없음)으로 돌려주므로 빈 목록이 정상처럼 통과했고, Polly(`SendWithRetryAsync`)는 예외·5xx·429·408만 재시도하므로 걸리지 않았습니다.

피해가 큰 쪽은 `ReconcileAsync`였습니다 — 보유 수량을 전부 0으로 읽어 전량 미체결로 판정하고, 수량이 줄어든 종목도 없으므로 **실제로는 체결된 달의 `DCA_LAST_RUN_MONTH`를 해제**했습니다. 다음 크론이 템플릿 전량을 다시 샀습니다. 이제 `rt_cd != "0"`이면 예외를 던지고, 호출부가 모두 `try/catch`를 가지고 있어 대사는 스냅샷을 보존한 뒤 다음 실행에서 재시도합니다.

### `appsettings.example.json` 삭제
자신을 `appsettings.local.json`으로 복사하라고 안내하면서 `Dca.Quantities`에 실제 티커·수량을 담고 있었습니다. `appsettings.json`이 의도적으로 비워 둔 값을 정면으로 무력화하는 파일이라, DB 조회 실패 한 번이 실제 매수로 이어질 수 있었습니다. 설정 키의 단일 진실 원천은 `Documents/reference/CONFIG_REFERENCE.md`입니다.

### 스케줄러 선택 확정
- **GitLab CI 이전: 기각.** 두 워크플로우는 `actions/checkout`도 없는 순수 `curl`이라 CI가 주는 것은 타이머뿐입니다. 상세 근거는 `[2026-08-07] 01_AutoInvesting GitLab CI 이전 검토.md`.
- **인앱 타이머(`BackgroundService`): 만들었다가 전량 되돌림.** Render 무료 인스턴스는 유휴 시 잠들어 타이머가 오류 없이 멈춥니다. 비수면 인스턴스는 유료라 채택하지 않았습니다. 트리에 구현체는 남기지 않고 `.agents/rules/architecture.md`에 금지 규칙만 신설했습니다.
- **cron-job.org 2차 소스: 기각**(사용자 판단).
- 결론: 트리거는 GitHub Actions 하나, `daily-run.yml` 크론은 `'10 15 1-31 * *'` 그대로 둡니다.
- 함께 기록한 제약: **2차 트리거를 추가한다면 1차와 최소 2시간을 띄워야 합니다.** `RunDcaCycleAsync`에 락이 없고 `dca-run`은 작업 전에 202를 반환하므로, 겹치면 양쪽이 빈 마커를 읽고 **둘 다** 삽니다.

### 문서 드리프트 감사 반영
검증된 드리프트·삭제 대상 95건(약 34개 파일, 순 약 -2,350행)을 이 세션에 적용했습니다.

## 정리 / 결론
- 중복 매수 경로 2건 차단 완료. 원인은 둘 다 "조용한 성공"이며, 원칙은 **판정 근거를 못 읽으면 멈춘다 / 업무 오류를 성공으로 읽지 않는다**입니다.
- 스케줄러는 GitHub Actions 단일 유지로 확정(대안 3건 기각).
- 다음 단계
  - 이 세션의 커밋 4건이 **아직 push되지 않았습니다.** push는 Render 재배포를 유발하므로 명시적 승인 후 진행합니다.
  - `appsettings.json` 전체 삭제 여부가 미결입니다. 기능상 무해함은 확인됐으나(모든 값이 C# 기본값과 동일, `Logging` 섹션은 읽는 코드 없음 — Serilog는 `Utils/Logger.cs`에서 코드로 구성), 삭제 전에 "`Dca:Quantities`는 비워 둔다" 규칙과 `Tax` 기본값을 `CONFIG_REFERENCE.md`로 옮겨야 합니다.
  - **"크론이 아예 돌지 않았다"를 알려 줄 외부 dead-man switch가 아직 없습니다.** 이번 장애에서 드러난 유일한 미해결 과제입니다.
