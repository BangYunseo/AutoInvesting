# 수동주문 보유종목 연동 + 대시보드 계좌 모드 표시

## 개요
> 실계좌 전환에 대비해 수동주문을 실제 보유 종목 기반으로 바꾸고, 대시보드에 계좌 모드(모의/실거래) 배지와 마스킹 계좌번호를 노출하는 작업이다.

## 배경 / 목적
실계좌 전환을 대비한 두 가지 개선을 진행한다.

1. **수동주문을 보유 종목 기반으로**: 종목코드 자유입력 대신, 실제 보유 종목을 끌어와 그 중에서 매수/매도.
   - 매도(SELL): 보유 종목만 선택 + 보유수량 상한.
   - 매수(BUY): 보유종목 드롭다운 + "신규 직접입력(검증)" 하이브리드.
2. **대시보드 실계좌 연결 가시화**: 계좌 모드(모의/실거래) 배지 + 계좌번호 마스킹 표시.

## 본문
### 계획
1. (백엔드) `OrderController.PlaceManualOrder`에 SELL 서버측 가드 — 미보유/보유초과 매도 400 차단.
2. (백엔드) `SessionManager`에 계좌 모드·마스킹 계좌번호 노출 → `PortfolioController.summary` 응답에 `accountMode`/`accountMasked` 추가.
3. (프론트) `Order.jsx` 수동주문 종목 선택기 — 보유종목 드롭다운(매도 상한) + 매수 신규입력 토글.
4. (프론트) `Dashboard.jsx` 상단 계좌 배지 + 마스킹 계좌번호.
5. Sim(`IS_PAPER_TRADING=1`) 검증 + `dotnet build`.

### 진행 및 결정
- 기존 현황: 백엔드 `/api/portfolio/summary`가 이미 실잔고(보유·예수금·환율)를 반환, 대시보드도 이미 사용 중.
- 대시보드는 새로고침/갱신시각/에러상태가 **이미 구현됨** → 신규는 계좌 배지+마스킹뿐.
- 계좌 모드 판정: KIS 키 없음=SIM / KIS_SERVER=prod=LIVE / vps=PAPER.
- (완료) 1. OrderController SELL 가드: 미보유/보유초과 매도 시 400.
- (완료) 2. SessionManager.GetAccountInfo() + MaskAccount(앞4·끝2) → summary에 accountMode/accountMasked 추가.
- (완료) 3. Order.jsx: 보유종목 드롭다운(매도 보유수량 max·전량 버튼), 매수 보유/신규입력 토글, 신규 /api/price 검증.
- (완료) 4. Dashboard.jsx: 상단 계좌 모드 배지(LIVE 빨강 경고/PAPER/SIM) + 마스킹 계좌 + 갱신시각/새로고침.
- (완료) 5. `dotnet build` 오류 0, `npm run build` 성공.
