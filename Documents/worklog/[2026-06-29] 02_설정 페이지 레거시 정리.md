# 설정 페이지 레거시 항목 정리 및 명칭 통일

## 개요
> 설정 페이지에 남아 있던 Phase 4~5 판단 레이어(퀀트/AI/리밸런싱) 잔재 설정을 제거하고, 네비게이션 항목명과 페이지 제목을 "설정"으로 통일한 작업이다. main 커밋·푸시·배포까지 완료했다.

## 배경 / 목적
설정 페이지(구 "시스템 설정")에 Phase 4~5 판단 레이어(퀀트/AI/리밸런싱) 잔재 설정이 남아 있어 현재 Phase 6(DCA 적립) 아키텍처와 맞지 않는다. 필요한 설정만 남기고 불필요한 설정을 제거하며, 네비게이션 항목명("설정")과 페이지 제목("시스템 설정")이 달라 혼란스러우니 "설정"으로 통일한다.

## 본문
### 계획
1. 설정 페이지/ConfigController에서 각 설정 키의 실제 소비처를 grep로 확인.
2. 유지: `IS_PAPER_TRADING`(SessionManager), `KIS_*`/`KIS_SERVER`(KIS 인증).
3. 제거(소비처 없음 — 판단 레이어 잔재):
   `ACTIVE_STRATEGY`, `INVEST_AMOUNT_KRW`, `ORDER_SCHEDULE`, `REBALANCE_THRESHOLD`,
   `AI_PROVIDER`/`GEMINI_MODEL`, `GEMINI_API_KEY`(시크릿) 및 `gemini-models` 엔드포인트.
4. 페이지 제목 "시스템 설정" → "설정"로 통일.
5. 빌드 확인.

### 진행 / 결정
- grep 결과: 위 제거 대상 키는 Core/비즈니스 로직에 소비처가 전혀 없고 ConfigController/AppConfigManager에서만 에코됨. 인앱 스케줄러(BackgroundService) 부재 확인 → ORDER_SCHEDULE 사실상 죽은 설정.
- DCA 예산·목표비중은 별도 "적립 설정" 페이지(DcaSettings)에서 편집하므로 시스템 설정과 무관.
- appsettings.json / AppConfigManager의 레거시 폴백 매핑은 무해한 기본값이라 이번 범위에서는 보존(과도한 범위 확대 방지).

### 완료 내역
- Settings.jsx: 활성전략/투자금액/스케줄/리밸런싱/AI모델 카드 제거, Gemini 키를 시크릿 모달에서 제외, AI 모델 조회 로직(geminiModels/fetchGeminiModels) 삭제, 페이지 제목 "시스템 설정" → "설정".
- ConfigController.cs: GET 응답을 IS_PAPER_TRADING/KIS_SERVER/KIS_*_SET로 축소, GEMINI_API_KEY를 reveal 화이트리스트에서 제외, gemini-models 엔드포인트 및 미사용 HttpClient/using 제거.
- dotnet build 0 error / 0 warning, Frontend npm run build 성공.

## 정리 / 결론
- 판단 레이어 잔재 설정 제거와 명칭 통일을 마치고 main 커밋·푸시로 Render 재배포까지 완료했다.
- 사용자 테스트(모의 모드에서 설정 페이지 진입/거래모드 토글/API키 모달 동작)를 확인한 뒤 커밋하는 흐름으로 진행했다.
- 후속(선택) 작업: appsettings.json Trading 섹션 및 AppConfigManager 레거시 매핑 정리는 범위 확대를 피하기 위해 별도 작업으로 미룸.
