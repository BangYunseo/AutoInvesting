# 260629 시스템 로그 DB 영구 저장 전환

- 상태: 진행중
- 작성/갱신: 260629

## 목적 / 요청
거래내역의 "시스템 로그" 탭이 (1) 파일명 형식 불일치 버그로 날짜 조회가 깨져 있고,
(2) `retainedFileCountLimit:7`로 7일만 보관되며, (3) Render의 휘발성 파일시스템 때문에
재배포·재시작 시 로그가 사라져 사실상 당일 것만 보인다.
→ 로그를 PostgreSQL에 영구 적재해 재시작에도 보존되고 날짜별 조회가 정상 동작하게 한다.

## 계획
1. `create_tables.sql`에 `TB_SYSTEM_LOG`(+ LOG_DATE 인덱스) 추가 (IF NOT EXISTS, 멱등).
2. `Data/DAO/SystemLogDAO.cs` 신규: Insert / GetByDate / GetAvailableDates / PruneOlderThan.
3. `Utils/Logger.cs`: Data 직접 참조로 인한 순환(Data→Utils) 방지를 위해 `Action` 훅
   `DbSink`만 두고, Info/Warn/Error/Fatal/LogQuant에서 Persist 호출(실패는 콘솔로만 — 재귀 방지).
4. `Program.cs`: DBManager 초기화 직후 `Logger.DbSink = SystemLogDAO.Insert` 연결 + 90일 prune.
5. `Controllers/HistoryController.cs`: 파일 대신 DB(SystemLogDAO)에서 로그 조회. 응답 형식 유지(프론트 무변경).

## 진행 / 결정
- 결정: Logger는 Data를 참조하지 않고 `DbSink` 델리게이트만 노출 → 조립 지점(Program.cs)에서 주입.
  (레이어 의존성 규칙 + 순환 회피)
- 결정: DB 적재는 DBManager 생성(Lazy 팩토리) 완료 후에만 활성화 → 초기화 중 재귀/Lazy 예외 방지.
- 결정: 응답 라인 형식을 `[시각] [LEVEL] 메시지`로 통일해 프론트 색상 규칙([ERROR]/[WARN]/[QUANT]) 유지.
