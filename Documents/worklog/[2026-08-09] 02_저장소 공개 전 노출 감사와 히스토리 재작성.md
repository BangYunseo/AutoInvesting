# 저장소 공개 전 노출 감사와 히스토리 재작성

## 개요
> 저장소를 public으로 전환하기 전에 워킹트리·git 히스토리·문서·프론트엔드·인프라를 대상으로 노출 감사를 돌리고, 그 결과에 따라 히스토리를 한 번 재작성했다. 자격증명 노출은 없었고, 실제 문제는 계정 ID와 회사명이 과거 커밋에 남아 있는 것이었다.

## 배경 / 목적

포트폴리오 목적으로 저장소를 public으로 열려면 히스토리 전체가 함께 공개된다. 파일을 지우는 것만으로는 과거 커밋의 내용이 사라지지 않으므로, 무엇이 남아 있는지 먼저 확인해야 했다.

특히 이 저장소는 2026-07-02에 이미 한 번 히스토리 세탁을 한 이력이 있어, 그 작업이 실제로 성공했는지 검증하는 것이 감사의 핵심 항목 중 하나였다.

## 본문

### 감사 방식

여섯 개 관점(워킹트리 시크릿, git 히스토리, 문서·개인정보, 프론트엔드·인프라, 공격 표면, 공개 위생)으로 병렬 조사하고, 각 발견 항목을 별도 검증 단계에서 "과장됐다"는 입장으로 반증 시도했다. 검증에서 살아남은 항목만 조치 대상으로 삼았다.

이 방식이 실제로 효과가 있었다. 세 개 관점이 HIGH로 올린 항목 중 다음 셋은 검증에서 전부 반증됐다.

- **배포 URL 하드코딩** — 워크플로에 평문으로 있으나, 인증 필터가 서버 키 부재 시 401을 내는 fail-closed 구조이고 인증 면제 액션은 둘뿐이다. 서브도메인이 저장소명과 같아 숨겨도 효과가 없다.
- **로그인 스로틀을 이용한 소유자 영구 잠금** — 유효한 크론 키 보유자를 상한에서 면제하는 경로가 이미 구현돼 있고, 1분 고정창이라 자동 해제된다.
- **미인증 DB 증폭** — 익명 도달 가능한 액션이 없어 성립하지 않는다.

### 확인된 문제

검증을 통과한 항목은 셋이었다. 전부 자격증명이 아니라 **식별정보**였다.

1. **본인 계정 ID 평문** — 과거 worklog 파일 본문에 남아 있었다. 원인이 뼈아프다. 2026-07-02에 히스토리 세탁을 하고 나서, **그 작업을 기록한 보고서 본문에 세탁 대상 문자열을 그대로 다시 적어 커밋**했다. 세탁 자체는 성공했으나 보고서가 값을 되살린 것이다.
2. **같은 ID가 설정 파일 값으로** — 로컬 전용 브랜치에만 있었고 원격에는 올라간 적이 없었다.
3. **재직 회사명** — 커밋 메시지 한 건에 남아 있었다. 파일 본문은 이전 작업에서 이미 `[개인]`으로 정정된 상태였다.

부수적으로, 로컬 `.git`의 도달 불가 커밋 안에 실제 증권사 자격증명과 계좌번호가 살아 있었다. `git rev-list --all` 기준 히트가 0이라 원격에 올라간 적은 없어 공개와는 무관했지만, 디스크에 남아 있을 이유가 없어 함께 정리했다.

### 감사 결과와 실제 상태의 차이

감사는 방치된 원격 브랜치 두 개에도 같은 값이 있다고 보고했으나, 실제 원격에는 `main` 하나뿐이었다. 로컬의 remote-tracking 참조가 스테일했던 것이다. `git ls-remote --heads origin`으로 확인하고 `git remote prune origin`으로 정리했다.

교훈은 **원격 상태를 로컬 캐시로 판단하지 않는다**는 것이다. `git branch -r`은 마지막 fetch 시점의 스냅샷이다.

### 조치 순서

```bash
# 1. 백업 (되돌릴 유일한 수단)
git clone --mirror . E:/Develop/Github/AutoInvesting-backup-20260809.git

# 2. 방치 브랜치 정리
git remote prune origin
git branch -D feature/phase5-feedback-loop

# 3. 도달 불가 오브젝트 제거 (자격증명 흔적)
git reflog expire --expire=now --expire-unreachable=now --all
git gc --prune=now

# 4. 히스토리 재작성 (치환 파일은 저장소 밖에 생성)
python -m git_filter_repo \
  --paths-from-file <임시폴더>/paths.txt --invert-paths \
  --replace-text <임시폴더>/replace.txt \
  --replace-message <임시폴더>/msg.txt \
  --mailmap <임시폴더>/mailmap.txt \
  --force

# 5. origin 재등록 (filter-repo가 제거한다)
git remote add origin <저장소 URL>
```

`git filter-repo`는 PATH에 등록되지 않아 `python -m git_filter_repo`로 호출했다. Microsoft Store 배포 Python은 스크립트 설치 경로가 표준 위치와 달라 PATH를 고치는 것보다 모듈 직접 호출이 짧다.

치환 파일은 **저장소 밖 임시 폴더**에 만들었다. 2026-07-02 작업에서 저장소 경로에 생성이 실패한 전례가 있고, 저장소 안에 두면 그 파일 자체가 값을 담은 채 커밋될 위험이 있다.

값은 직접 타이핑하지 않고 히스토리 블롭에서 패턴으로 추출해 파일로 썼다. 값이 명령행이나 작업 기록에 남지 않게 하기 위해서다.

### 제거한 경로

| 경로 | 이유 |
|---|---|
| 환율우대·환전경로 비용 분석 2건(구·신 파일명) | 월/연 적립 규모, 실측 환전 내역, 거래 은행·증권사 조합, 예탁자산 등급 역산 가능 |
| 존속 진단·포트폴리오 평가·채점 진단 4건 | 자체 채점 결과와 약점 목록을 순위까지 나열한 문서. 포트폴리오로 저장소를 여는 목적과 정면 충돌 |
| `docs/` 전체 | 마스킹 전 v1 스크린샷과 base64 인라인 HTML이 과거 커밋에 남아 평문 단가가 그대로였다. 히스토리에서 제거한 뒤 마스킹본만 새 커밋으로 다시 올렸다 |

백테스트 검증 문서와 재현 스크립트, 절세 가이드는 **남겼다**. 공개 ETF 분석이라 식별정보가 없고, 소개 페이지 백테스트 표의 근거 문서이기 때문이다. 근거 없는 수치만 남기는 편이 더 나쁘다.

### 티커 통일

문서·코드·테스트에 흩어져 있던 실제 보유 종목 티커를 예시 티커로 통일했다(25개 파일). 전부 XML 주석, DTO 설명, 테스트 픽스처, 입력 placeholder라 동작에는 영향이 없다.

`Core/KisBrokerClient.cs`의 거래소 코드 매핑 주석 3건은 **예외로 두었다**. 특정 ETF가 어느 거래소에 상장돼 있어 시세 코드와 주문 코드가 어떻게 갈리는지 설명하는 기술 서술이라, 가상 티커로 바꾸면 틀린 문서가 된다.

한계도 분명하다. 소개 페이지 스크린샷에는 티커가 그대로 보인다. 금액·수량은 마스킹했으나 종목명은 남기기로 한 결정이므로, 티커 통일의 실효는 "문서 일관성" 쪽이지 노출 차단 쪽이 아니다.

### 검증

```bash
git log --all --oneline -S'<토큰>' | wc -l          # 0
git log --all --format='%s%n%b' | grep -c '<회사명>'  # 0
git log --all --format='%ae%n%ce' | grep -c '@gmail.com'  # 0
git log --all --name-only --format="" | grep -c '^docs/'  # 0
dotnet build                                        # 오류 0
dotnet test Tests/AutoInvest.Tests.csproj           # 57 통과
```

커밋 수는 355에서 345로 줄었다. 내용이 전부 제거되어 빈 커밋이 된 것들이 정리된 결과다.

## 정리 / 결론

- 감사 결과 판정은 **FIX_FIRST**였다. 차단 사유(BLOCKER)는 없었고, 식별정보 3건을 선처리하면 public 전환이 가능하다.
- 워킹트리와 HEAD에 실제 자격증명은 없었다. 설정 파일의 시크릿 자리는 전부 자리표시자였고, Actions 워크플로도 전 히스토리에서 리터럴 키가 0건이었다.
- 조직 보안정책이 금지하는 항목(주민번호·휴대폰번호·비밀번호·DB 접속정보)은 워킹트리·문서·히스토리 어디에도 없었다.
- 히스토리 재작성 1회로 계정 ID·회사명·개인 메일 주소·삭제 대상 문서·마스킹 전 스크린샷을 한 번에 제거했다.

남은 일:

1. **원격 강제 푸시** — `git push --force-with-lease origin main`. 재작성된 히스토리를 원격에 반영해야 조치가 실제로 완료된다. 푸시 전까지 원격에는 옛 히스토리가 그대로 있다.
2. **저장소 public 전환** — 푸시 완료 후.
3. **GitHub Pages 활성화** — 저장소 설정에서 `main` 브랜치 `/docs`를 배포 소스로 지정. 무료 플랜은 private 저장소에서 Pages를 켤 수 없으므로 public 전환이 선행돼야 한다.
4. **백업 미러 처리** — `AutoInvesting-backup-20260809.git`에는 재작성 전 히스토리가 그대로 있다. 푸시와 공개가 끝나 되돌릴 일이 없어지면 삭제한다. 절대 push 하지 않는다.
5. **재발 방지** — 세탁 보고서에 세탁 대상 값을 다시 적지 않는다. 이번 사고의 원인이 정확히 그것이었다.
