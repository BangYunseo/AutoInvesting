# 절세 보조기능 MVP 구현

## 개요
> 매도 시 과세 구간이면 예상 세금·수수료를 프리뷰로 알려주고, 확인(ack) 없이는 과세 매도가 실행되지 않도록 서버에서 차단하는 절세 보조 기능(MVP)을 구현한 작업이다. `feature/tax-guard` 브랜치에서 구현·검증까지 마쳤고 사용자 테스트를 기다리는 미머지 상태다.

## 배경 / 목적
매도 시 과세 구간이면 예상 세금·수수료를 알려주고, 과세 매도는 확인(Alert) 없이는 실행되지 않게 서버에서 차단한다. 판단/타이밍이 아니라 세금 산수 기반의 정보/가드다.

설계 문서는 `Documents/260702_절세보조기능-설계계획서.md`, 근거 자료는 `Documents/analysis/260702_해외ETF-절세-가이드.md`이다.

## 본문
### MVP 범위와 설계 결정
- MVP 범위: 프리뷰 + 경고 + 서버 강제 차단. YTD 실현차익은 **수동 입력**으로 처리하고, DB 스키마 변경은 2차로 연기한다.
- 계산은 순수 함수 `TaxEstimator.Estimate`로 분리해 단위 검증이 가능하게 하고, 설정 로딩만 `TaxSettings.Load`가 담당한다.
- 취득가는 브로커 `HoldingDto.AvgPrice`를 사용한다. 취득가가 불명(0 이하)이면 가드를 건너뛴다(오차단 방지).
- 과세 매도인데 `acknowledgeTax=false`면 `OrderController.manual`이 **409 + taxEstimate**를 반환한다.

#### 수정 파일

- `Frontend/src/pages/Order.jsx`: 프리뷰 조회 → 금액 명시 확인창 → ack 제출 + YTD 입력 필드

#### 검증
- `dotnet build` 오류 0
- `dotnet test` 19건 통과
- `npm run build` 성공

### 남은 작업
1. **SimBroker(`IS_PAPER_TRADING=1`) 실동작 검증** — 매도 프리뷰·409 가드·확인창 흐름.
2. **사용자 직접 테스트 후 승인** → 그 뒤에만 `main` 머지(fast-forward) + push(재배포).
3. **문서 동기화**: `project_overview.md` 디렉토리 표 / `DEVELOPMENT.md`에 신규 파일·엔드포인트 반영(머지 시).
4. (2차) YTD 지속성: `TB_TRADE_HISTORY` nullable 컬럼(COST_BASIS_USD/REALIZED_GAIN_KRW/FX_RATE) + `GetYtdRealizedGainKrw`.

### 관련 파일
- `Core/TaxEstimator.cs`, `Data/DTO/SellTaxEstimateDto.cs`, `Controllers/OrderController.cs`, `Frontend/src/pages/Order.jsx`, `appsettings.json`, `Tests/TaxEstimatorTests.cs`
- 브랜치: `feature/tax-guard`

## 정리 / 결론
- 프리뷰·경고·서버 강제 차단(409)까지 MVP 구현이 끝났고 빌드·테스트·프론트 빌드 검증을 통과했다.
- 세금 계산은 순수 함수(`TaxEstimator.Estimate`)로 분리해 단위 검증이 가능하며, 판단/타이밍이 아닌 정보/가드 성격을 유지한다.
- 아직 `main`에 머지하지 않은 상태로, SimBroker 실동작 검증과 사용자 직접 테스트·승인 후에만 머지·재배포한다.
