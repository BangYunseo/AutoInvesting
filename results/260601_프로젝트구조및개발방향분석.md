# 프로젝트 구조 및 향후 개발 방향 분석 보고서

## 1. 현재 프로젝트 상태 (Phase A 완료)
현재 AutoInvesting 프로젝트는 **WinForms 기반 데스크톱 애플리케이션에서 Headless ASP.NET Core Web API 백그라운드 서비스로 성공적으로 마이그레이션(Phase A)** 되었습니다. UI 스레드에 종속되었던 레거시 코드들이 모두 제거되었으며, 서버 환경에서 24시간 안정적으로 자동 투자 프로세스를 구동할 수 있는 구조를 갖추고 있습니다.

### 핵심 아키텍처 개요
- **진입점 (`Program.cs`)**: ASP.NET Core DI(의존성 주입) 및 미들웨어 설정 적용. `Serilog`를 통한 로깅 적용 확인.
- **백그라운드 스케줄러 (`TradingBackgroundService`)**: IHostedService 인터페이스를 구현하여 상시 구동되며, 예약된 시간에 `SmartOrderEngine` 등을 호출.
- **REST API (`Controllers/`)**: 기존 WinForms 패널들을 대체하여 외부(웹 대시보드 등)에서 호출할 수 있는 `OrderController`, `StrategyController` 등의 엔드포인트 마련.
- **코어 비즈니스 (`Core/`)**: `SmartOrderEngine`과 퀀트 조건 판단 모듈(`Quant/`), 증권사 API 클라이언트(`KisBrokerClient`, `SimBrokerClient`) 유지 및 연동 완료.
- **데이터 레이어 (`Data/`)**: SQLite 및 DTO/DAO 패턴 기반으로 마스터 데이터, 거래 기록, 시장 스냅샷(`TB_MARKET_SNAPSHOT`) 관리.
- **환경 설정**: 기존 App.config 방식에서 `appsettings.json` 및 시스템 환경변수 기반으로 변경되어 보안성 강화.

## 2. 기존 룰(Rules) 문서와의 차이점
- 기존 제공된 `.agents/rules` 관련 텍스트(예: `architecture.md`, `ui_theme.md`, `project_overview.md`)에는 WinForms 기반(`Panels/`, `AppTheme` 등)에 대한 내용이 포함되어 있으나, **실제 리포지토리의 README와 DEVELOPMENT.md 문서 상으로는 ASP.NET Core 기반으로 구조가 전면 개편**되었습니다. 
- 따라서 향후 개발 진행 시 UI 관련 컨벤션보다는 **REST API 및 백그라운드 서비스 중심의 컨벤션(로깅, 의존성 주입, 예외 처리 등)을 최우선**으로 따라야 합니다.

## 3. 향후 개발 제안 방향 (Next Steps)
프로젝트 로드맵 및 이전 작업 내역을 바탕으로 볼 때, 현재 진행할 수 있는 주요 목표는 크게 두 가지 방향(안정성 강화 vs 신기능 확장)으로 나뉩니다.

### 📌 선택지 1: Phase B/C (운영 안정성 및 프론트엔드 확장)
시스템을 실전에 더욱 견고하게 투입하고 모니터링을 고도화하는 작업입니다.
1. **API 호출 내결함성(Fault Tolerance) 강화**: KIS API 호출 시 발생할 수 있는 네트워크 오류, 429(Rate Limit) 예외 등에 대해 `Polly` 라이브러리를 적용하여 **재시도(Retry) 및 지수 백오프(Exponential Backoff)** 로직 추가.
2. **이메일/모바일 알림 기능**: 거래 체결 내역이나 시스템 오류 발생 시 **Naver SMTP 등을 활용한 알림 발송** 서비스(`NotificationService`) 구축.
3. **React 기반 웹 대시보드(모바일 뷰) 구현**: 완성된 ASP.NET Core REST API를 호출하여 시각적으로 상태를 확인할 수 있는 SPA 프론트엔드 프로젝트(Day Loop) 연동 개발 시작.

### 📌 선택지 2: Phase 4 (AI 시장분석 엔진 확장)
기존에 구축해 둔 `TB_MARKET_SNAPSHOT` 데이터를 활용하여 퀀트 투자의 판단 능력을 고도화하는 작업입니다.
1. **AI / ML 기반 신호 분석기 (`IMarketAnalyzer`) 인터페이스 신설**.
2. **지표 연동 및 Scoring**: 수집된 RSI, MACD, 스냅샷 기록을 바탕으로 단순 조건(AND 조건) 필터를 넘어 점수(Confidence Score) 기반의 유연한 판단 로직 구현.
3. Python 기반의 분석 스크립트(Night Loop)를 API 서버에서 호출하거나 스케줄링하여 연동하는 아키텍처 설계.

## 4. 결론 및 건의 사항
시스템 구조가 이미 웹서버 형태로 잘 정착되어 있으므로, 퀀트 투자의 핵심인 **[안정성 강화(Polly 적용 및 알림 서비스 추가)]** 부터 먼저 완료한 후, **[React 웹 대시보드 연동]** 혹은 **[AI 모듈 개발]** 로 넘어가는 것을 추천해 드립니다. 

원하시는 방향을 선택해 주시면 즉시 관련 코드 작업 및 마크다운 설계(Implementation Plan)를 진행하겠습니다.
